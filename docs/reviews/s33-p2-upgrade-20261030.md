## 目标与实现

依据[计划§16.15](../product/05-第一阶段实施计划.md#1615-p2工作根升级的产品入口目标契约)，R3双面评审，沿用sop-spec-delivery／security-design／frontend／docs及既有Sk品牌。设计B首轮两项P2已关闭，A／B第2轮APPROVE；规范核心与记录见[plan-review.json](s33-p2-upgrade-20261030/plan-review.json)。

MCP设置页新增“诊断存储”。读取不新增v4备份／DDL；LocalState原有首次开根v1／v2→v3行为保持。确认弹层显示当前根、备份及旧版本不能打开的提示，勾选后“备份并开启”；提交前取消零升级请求，提交中不允许中途取消。成功保留服务草稿，配置仍需单独保存，诊断仍需用户手动启动。前后端状态分开，只有核验v4才能诊断。

窄IPC只接当前LocalState根及确认token，不接任意路径／SQL／目标版本。token绑定canonical application／workspace、数据库dev／ino、版本及完整schema摘要，是陈旧确认防错，不是权限密钥。确认重新预检，持有共享空槽锁再访问存储；业务／模型／角色／MCP任务或清理占槽均拒绝。并发同token只能完成一次升级及备份。

复用原WAL一致备份、私有文件身份／同步、DDL前核验及事务迁移。成功回执才展示本次有效备份；不扫描遗留文件并冒认有效，不自动还原、降级或重试。明确DDL前拒绝可重新预检和人工确认；DDL／复制／提交未知在当前句柄阻断MCP，必须重开核对。传输响应丢失只在同workspace核验v4后解除；v3、换根或读取失败继续保留未知。

专用验证包增加`controlled-upgrade-no-credentials` scope，从固定隔离v3开始，可在未来获准后通过同一生产IPC操作升级；旧`controlled-no-credentials`仍自动隔离v4。两者保留nonce／根身份／指针及模型文件禁用护栏，native-info记录实际版本。仅编译与隔离护栏测试，没有启动原生窗口。普通包仍不提供验证scope入口。

## 恢复与剩余项

备份失败未跑DDL；遗留文件不能当有效备份。迁移或提交unknown保留当前库、WAL／SHM及备份，不覆盖。请关闭并重开当前新版应用核对；只有结构与完整性验证成功才展示已开启。需要还原时先关闭应用、核实已确认备份与当前文件，另行安排；没有提供“一键还原”或执行真实恢复。旧版本守卫仅源码隔离证据，真实旧原生包兼容保持未验。

本轮实现普通根产品触发入口，但未升级真实普通根；普通打开仍最高自动v3，不因进入页面自动v4。真实MCP适配器保持硬关闭、没有启用开关，GUI安全值真实持久化未开放。完整`npm run check`仍待允许旧受控tools/call与S0合成登录Keychain条目读写删除；原生`getApp`先前以-10005／ScreenCaptureKit -3811失败，本轮未重试，父报审批卡映射未独立确认。两尺寸原生完整动线、第三方MCP兼容、P3／P4和全部历史原生缺项不因本步代码／替身通过而关闭；P2整体继续开放。
