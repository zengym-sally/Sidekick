## 4. 设置按对象组织，保存范围明确

| 页面 | 信息分组／空间安排 | 操作位置与关键分支 |
|---|---|---|
| 个人信息 | 昵称、班班称呼一组；预览靠近字段 | 底部保存；默认小明同学／BOSS，支持与昵称一致。左下只显示昵称，设置激活态与主导航一致，无箭头 |
| 通用 | 工作目录、日期与时间两行分组，左说明右字段 | 路径尾部选择／打开；时区底部保存。切换目录是独立操作 |
| 模型服务 | 供应商列表＋服务字段＋模型表；模型普通字段在前，高级参数渐进展开 | 当前服务／当前模型底部保存；测试连接在对象标题右侧，先保存再测；全局默认选择后用右侧“应用”显式生效 |
| 智能体 | 三个固定角色；配置与试跑双栏 | 底部保存当前角色；试跑位于样例旁；有脏配置时不能试跑；恢复默认只修改当前角色草稿，保存生效 |

普通窗口保持稳定侧栏；较窄窗口收为图标导航，模型供应商横向排列，智能体上下布局。1440×1000、1240×820为主要桌面验证，640×900仅检查窄窗口回退，未增加移动端产品。长模型参数允许内容区滚动，保存栏不跟随内容消失。

各 Tab／供应商／模型／角色保留独立草稿，切换不自动保存、不覆盖别的草稿。底部只保存当前对象；更换全局默认有自己的“应用”，不混入供应商保存。未来真实实现须处理保存中、冲突、结果未知／读回恢复，沿用已存在事务与修订契约，不能用原型的同步内存赋值替代。刷新原型重置所有演示数据，和真实应用的重启恢复是不同验证对象。

## 5. 模型字段分三层，配置界面与实际接线分开验

核对 WorkBuddy 的 `providers.example.json`、`models.example.json`，以及固定 Pi 快照 `ad702637fdf6fbd3f965c5dba0b14bae100b74eb` 的 `packages/ai/src/types.ts`、当前 `runtime/organizer-entry.mjs` 和 `src-tauri/src/model_config.rs`。判断以本地锁定源码为准；不将上游最新能力算作已接入。

| 层／字段 | 当前真实接线 | 本轮 GUI 提案与实施边界 |
|---|---|---|
| provider：id/name/apiFormat/baseUrl | OpenAI-compatible 经宿主校验，Runtime映射为 openai-completions | 稳定ID由应用管理；显示名、地址可配置；协议先只呈现当前支持路径，不做假协议选项 |
| auth：API Key／apiKeyEnv | 当前支持钥匙串引用及指定环境变量；前端不回读已有秘密 | GUI选择认证方式、密钥替换；旧Key留空保留。原型仅演示密码输入，不读写钥匙串 |
| network：timeoutMs/retry | 单请求1–120秒，重试0–2，总任务120秒约束仍生效 | 高级连接项；保存／测试分开，超时不承诺完整重试预算 |
| extraHeaders | 当前Runtime传入请求头；宿主拒绝明显秘密承载位置 | GUI仅非秘密固定头，真实实现需可增删多行；认证转凭据引用。原型仅展示一组行样式 |
| enabled | 当前已做引用有效性校验 | GUI开关；有全局／角色引用时先调整引用，不静默回退模型 |
| proxy/rateLimit/tags | 非空proxy当前拒绝；RPM/TPM未有调度执行保证 | 不给无效可编辑项；保留已有非秘密元数据。代理／限流调度另作明确需求与切片 |
| model：id/name/providerId/apiModelId | 逻辑ID与实际wire模型ID分开 | 模型归属供应商，GUI增改；不把显示名当API标识 |
| description/status/aliases | 配置可保留；不等同真实服务状态 | 显示名／说明／别名与启用供管理使用；“测试通过”仅指明确的一次调用与时间 |
| limits：maxInputTokens/maxOutputTokens | contextWindow默认32000；当前输出实际被上限4096钳制 | GUI支持填写目标规格；**不得无声钳制后称其已生效**。实施需先解决适配／预算，或显示阻止超出当前上限的校验 |
| capabilities：toolCall | 已参与工具集合控制；S3.1隔离试跑工具为空 | GUI能力声明；不代表工具或业务服务已经接通 |
| reasoning：supported/defaultEffort等 | Pi类型有reasoning/thinkingLevelMap；当前桥接写死reasoning:false | 拟接入；按端点支持映射，不盲目给所有端点相同effort。原型提示“拟接入”，不能只持久化不发请求 |
| defaultParams：temperature/topP | Pi有temperature与samplingParams；当前桥接未传 | 拟接入；OpenAI兼容topP需要映射为samplingParams.top_p；空值省略，推理模型按端点兼容处理 |
| pricing：currency/unit/input/output/cacheRead | 当前Runtime成本为占位0，不是实测价格／免费 | 仅本地可选记录，每百万tokens；未填保持未知，不做费用仪表盘、不联网抓价 |
| input/output多模态、streaming等声明 | 当前整理输入仅text，结构化输出有业务schema校验 | 不增设未支持的多模态开关；保留未知元数据不表示生效 |
| 全局默认／角色覆盖 | S3.1已存在，三个固定角色 | 按供应商分组选择，可继承默认；删除／停用有引用阻断，不能断开现有配置 |

**移除 JSON 导入是移除用户操作模式，不是改掉双层文件契约。** 原有 providers/models 文件、引用、钥匙串条目及未知非秘密字段需兼容保留。GUI读取、校验、保存仍走现有成对事务，不因布局重写而丢元数据或重置绑定；旧工作目录升级前后需有 round-trip 证据。

## 6. 时区集中设置，要同时统一真实时间逻辑

- 新输入的具体时刻、自然语言“今天／下周五”的理解与日期归组，使用应用保存的时区。首次值可取系统时区，保存后不随系统设置静默改变。原型提供四个常用示例；生产需统一可搜索IANA列表，不把四项当完整支持范围。
- 已保存的具体时刻以UTC保持不变，切换设置只变显示及归组；仅日期保留 civil date，不通过UTC往返把日期挪动。
- 来源时间是可选锚点，保留字段，不再让用户逐次填IANA时区。首次整理固定锚点与当时解析规则；既有来源／候选重试沿用原快照，不因后来改时区重新解释已捕获文本。
- 来源原时区可留在内部证据，不在普通页面重复提示。“仅日期／含时间”、截止／跟进的差异仍可见。夏令时不存在时刻须阻止并提示恢复办法，重复时刻需选择较早／较晚，不擅自猜。
- 原型用合成候选验证显示转换，公共日历验证选择／清空；真实实施需把 `currentZone()`、格式化、归组、解析、来源快照和日期控件一起切换。**删掉提示文案不等于完成统一时区。**

## 7. 目录两按钮的外观可先定，迁移不能混作布局小改

“打开目录”调用宿主揭示当前目录；“选择新目录”调用系统文件夹选择器。选中后需要独立预检／迁移流程：空目录或兼容工作根、空间及可写、任务停止、WAL一致备份、复制／校验、成功后切换bootstrap，失败继续原根。用户不得因点一个图标失去数据；原根不自动删除。

这部分原有阶段计划包含后续迁移工作，本轮只在原型演示“选择→预检说明→迁移切换”。**未提前交付迁移，也未把本轮布局确认等同于真实数据迁移执行授权。** 实施前将目录切换单列有恢复证据的切片，确认是否前移；其余布局可以独立完成。
