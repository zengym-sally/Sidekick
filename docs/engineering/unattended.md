# 跟班 Sidekick 无人值守运行约定

适用于owner明确启动的有界连续目标。授权事实与当前进度只记在[实施计划](../product/05-第一阶段实施计划.md)；工程边界、门禁分别沿用[工程架构](architecture.md)、[验证约定](verification.md)及[AGENTS.md](../../AGENTS.md)，不在本文件维护第二份状态清单。不得在无人值守执行中自行扩大或修改本手册；缺陷记入待决。

## 1. 启动、准入与时间

- 先轻量读取实施计划中的当前授权、选取阶梯与最近交接，再运行已安装`sop-unattended/scripts/run_guard.py`的acquire。路径由本机技能目录解析，不把个人绝对路径入库。
- 本队列独占、串行；使用`--exclusive`，同时用`--paths`明确实际源码／文档及构建产物目录，避免释放口径把空声明误报ESCAPED。认领覆盖本项全部可能写入路径，拿不准则保留独占，不并行开另一个主项。
- `acquire --item <项> --exclusive --paths <路径> ... --max-hours 1`；exit3为被拒，零实现产出退出。持有者在阶段结束及长命令前后`heartbeat --run-id <id> --max-hours 1`；exit4立即停止改动、保留现场。资格与最近报告位于Git公共目录的`.sop_sessions/`。
- `acquire`返回exit0但`reclaimed`非空，只证明租期接管，不证明旧执行已停。保存返回信息，先只读核对旧任务、进程、工作区和交接；旧acquire启动器PID已不存在也不构成旧执行已结束的证明。只有能确认本运行的旧项已中断且无其他写者、或owner明确允许接管时才续作；无法确认则保留现场、记待决、释放刚取得的资格并退出，不写源码、不删旧worktree、不重做旧动作。合成演练须覆盖“过期租期但旧执行仍活着”时的新持有者退出且工作区不变。
- 每个阶段核对UTC时钟并按Asia/Shanghai换算。到owner指定截止时间不再领取新项，先完成不可中断动作的安全收尾、留交接并释放资格，再将持续目标按owner要求暂停并汇报；不能用“时间到”把未完成项标完成。
- 目标全部通过则提前完成并汇报。机器／网络／桌面不可用按真实状态留痕，不重试绕过系统权限。

## 2. 选取阶梯

| 档 | 来源与触发 | 完成后 |
|---|---|---|
| L0 | 当前活动切片的回归／未关闭评审发现，有可核对证据且在已批准边界内 | 修复、回归、独立复审；不能绕过门禁进入下一项 |
| L1 | owner已确认的队列中第一个前置全部通过的项；当前顺序见实施计划 | 设计→反例→实现→聚焦／邻域→交付复核→一次稳定全量→独立核实→按授权提交 |
| L2 | 活动项已通过，仅缺状态同步、证据核对或提交核实 | 收口后重新选取，不另外发明功能 |

前置不满足、无可做项或截止已到，分别写明原因后收尾。不得用跳项补齐依赖，不从P4–P6扩展到HTTP、其他角色、桌宠或其他阶段。无人可答时不提问：用户所属的范围／契约／安全／数据／验收决定写待决；有独立且已授权的项才可继续，没有则保留现场。不能自签独立评审或接受阻塞风险。

## 3. 设计与独立评审

- 每项主流程用`sop-spec-delivery`，已证缺陷用`sop-bug-fix`，安全边界借用`sop-security-design`；R3使用持久规范核心、威胁与验证对应、恢复方案及全新上下文双面评审。
- owner预先允许已批准范围内的细化方案经独立评审准出即可实施；改变范围、权限、schema、依赖、标识或真实数据操作不在此代理决定权限内。
- 每个评审面只收到逐字规范核心、自己负责的判据、相关源码／固定快照及原始证据；不能读取共享续记里的其他面结论，也不使用会自动展开其他任务摘要的清单工具。汇总结论在两面封存后由主执行方记录；复审继续使用隔离输入。
- 修订→复评最多三轮；第三轮仍无APPROVE或评审面不可用，停止该项、保留发现与待决，不用测试绿证替代专家结论。只追加实际证据不重开未变的设计闸门。
- 同一主项可分派明确不相交的源码职责及只读评审；主执行方协调唯一写入归属。Cargo、打包及重门禁始终串行，不让不同源码版本交叉污染证据。

## 4. 模型请求预算与数据

- 真实模型只用owner指定的仓库根`.env.deepseek`；不回显密钥、不写进代码／日志／截图／数据库或提交，不扫描其他凭据。所有发出的正文、工具输入均为合成资料，MCP仅用本机受控服务；不动真实用户根。
- 当前启动的硬上限以实施计划授权为准，包含HTTP重试、重开及Agent后续轮次。首次真实请求前必须实现并独立验证原子预算门：先持久保留一次额度，再允许唯一上游请求；未发出或结果不明的保留额度也不退还。不得通过换计数文件、重置或直接运行旧live入口绕过。
- 权威计数作为原始执行证据保存在当前夜间证据目录的`model-budget.sqlite`；首次启动且确定尚无请求时独占建立，之后必须打开既有库，缺失／损坏／无法持久确认即停止真实请求。记录仅含槽号、阶段、时间、状态，不含头、密钥或正文。测试预算门使用独立临时计数与假上游，不消费真实额度。
- 所有真实上游请求必须经过同一个预算执行器，SDK透明重试也须计入；不能接管的live命令不运行。达到上限停止需要真实模型的部分，记录未验，不冒称完成或自动提高上限。
- 真实模型验证只暴露已批准的受控MCP工具及合成数据，不向它开放通用Read／Bash／Skills或真实目录；该限制只属于受控验证接缝，不删改产品原工具能力。原Read／Skills／Bash兼容性用合成回归另证。
- MCP生产钥匙串保持关闭；既有完整check中的S0专属合成Keychain往返许可沿用，不把它记作MCP生产后端通过。

## 5. 桌面与进程操作

- 只控制owner授权的Sidekick MCP Verify专用验收App，使用当前项独占新建的临时根／nonce；允许其截图、点击、键盘、构建后重开及本轮自有实例退出。普通Sidekick.app只构建／验签，不打开真实根。
- 不修改系统权限、窗口管理／显示设置或绕过控制工具。控制失败保留错误和未验项，不用合成界面或改图补签真实GUI。
- 只按run／nonce、脚本路径与实际进程身份回收本轮自有进程；不得按名字或过期PID扫杀。只清理本轮新建且归属可证的合成资源；历史唯一证据、旧根及未知来源worktree不自动删除。

## 6. 验证与收口

- 命令从package等项目配置读取。按聚焦→邻域／类型／fmt／Clippy→独立交付复核→稳定后一次完整`npm run check`（含两包／资源排除）执行；不删门禁、不扩大skip，不运行未接预算的真实模型用例。
- 先记录HEAD、工作集和冻结哈希；运行后比对字节、计数及警告类别。记录“exit0”和验证层的实际边界；假模型、替身、CLI、真实模型和原生证据分别署名，未验证不关闭。
- 按当次授权分项提交，提交前审查cached stat／name-status／package变化及卫生，提交后核对HEAD、parent、状态与源码冻结。不自动push、amend、force或改Git配置。未验证半成品不提交，保留可恢复现场。
- 状态写实施计划，分层证据写`docs/reviews/`并登记索引；原始日志／产物／请求计数进`build/<项>/`，精选摘要不含私密路径或凭据。
- 每项结束：`release --run-id <id> --outcome <结果> --changed <实际路径> ...`，再`log`一行实际结果；检查active已删除。本机独占模式仍显式声明路径，释放的ESCAPED须按真实改动核实，不用它扩大授权。
- 交接／待决按`sop-session`与`sop-unattended`固定五类放Git公共目录`.sop_sessions/`，当前态覆盖、已完成删行，日志有界；不另写记忆或并行状态副本。每项收口及长命令前后续期并核时。
