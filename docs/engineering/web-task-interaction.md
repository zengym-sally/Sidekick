# 浏览器任务交互：队列、取消与恢复的界面契约

> 面向 W0–W5 浏览器阶段的**任务面板**交互设计：默认 3 并发、持久排队、取消、失败与恢复核对的界面语义。
> 状态机、数据规则与失败语义以 [Web/后端设计](web-backend-design.md) §5 为权威，本文只定义「用户看到什么、能做什么、文案怎么说、焦点怎么走」。本文是设计，不实现 HTTP/SSE，不替代[用户流程](../product/02-用户流程.md)与[分期验收](../product/04-分期交付与验收.md)。
> 可交互演示：`design/web-task-flow/`（合成数据，不连接模型、飞书、MCP、Bash 或本机文件系统）。接口字段名以契约冻结为准，本文用设计文档已有的逻辑名称（taskId／操作幂等键／attemptId／实例 epoch／游标）。

## 1. 范围与边界

| 覆盖 | 不覆盖 |
|---|---|
| 模型任务（整理、修改、三角色试跑、今日建议、模型测试）的提交、排队、运行、取消、失败、待核对与恢复核对界面 | 业务结果本身的编辑与签收（见候选与事项动线） |
| 多客户端共享同一队列：刷新、重连、旧事件丢弃、页面关闭不取消任务 | 后端实现、DDL、依赖选型（按实施切片授权） |
| 凭据／配置不可用、备份恢复与旧根激活的暂停与逐项核对 | 真实凭据读取、真实工作根操作、Linux 部署 |
| 原生不可用能力在浏览器阶段的状态与入口；通知／桌宠／导航的壳适配点 | 正式壳层功能（D1 之后） |

面板对所有用户可见，不只是开发者工具：排队与取消是普通业务动线，不是诊断页。

## 2. 任务状态与界面语义

状态名沿用设计文档；界面标签对应用户语言。一个任务同一时刻只有一个权威状态，界面不自行推断或合并状态。

| 状态 | 界面标签 | 用户看到什么 | 可做什么 | 明确不做 |
|---|---|---|---|---|
| `queued` | 排队中 | 排队位置（第 N 位）、提交顺序、任务类型与输入摘要 | 取消（确定不执行） | 不显示预计等待时长 |
| `running` | 运行中 | 占用的执行槽（n/3）、当前阶段、attempt 标识 | 取消 | 不显示内部提示或原文内容 |
| `cancelling` | 取消中 | 「已记录取消意图，正在停止」、尚未确认退出、仍占用的执行槽（n/3） | 无（等待结果） | 不显示「已取消」、不释放执行槽 |
| `succeeded` | 已完成 | 结果入口（候选／建议／测试结论）与完成时间 | 查看结果 | 不把任务成功当作事项已签收 |
| `failed` | 失败 | 失败原因分类、输入是否保留、是否可重试 | 可重试时重试；否则重新提交或改配置 | 不无限重试、不自动重放 |
| `cancelled` | 已取消 | 取消时间与取消方 | 重新提交 | 不静默重新入队 |
| `interrupted` | 运行中断 | 后端重启／崩溃导致的最后一次运行中断，输入已保留 | 重新提交；有外部副作用的先核对 | 不自动重入队 |
| `needs_review` | 待核对 | 外部副作用结果不明，或恢复／激活后来源历史无法证明连续 | 逐项选择：已确认完成／标记失败／保留待核对 | 不自动重发、不按 queued 直接调度 |

状态同时有文字与图标（产品定义 §4）。`cancelling` 与 `needs_review` 是**未终态**：前者等进程退出确认，后者等用户明确选择；两者都不显示成功勾选状态。

## 3. 队列面板

### 3.1 结构与信息层级

面板固定三段，扫描优先：

1. **并发与槽位条**：`agentConcurrency` 当前值（默认 3）、占用的执行槽 n/3、排队 M 条。并发是实例级设置，入口在设置页；面板只读当前值并链接过去。下调不杀正在执行的任务，界面说明「已运行的任务会自然结束后再满足新上限」。
   - **占槽集合 = `running` + `cancelling`**：取消中未确认退出前不释放槽，因此槽位条、运行中计数、提交/重提闸门都必须按这个集合计算，避免「默认 3 实际超发」。
   - 槽位条把取消中一并点亮；统计区至少给出运行中、取消中（占槽）、排队中三个数字，aria-label 说明取消中为什么仍占槽。任务行内 `cancelling` 的徽标带「槽 n/3」。
2. **任务列表**：按持久提交顺序排列，运行中的按领取顺序在前。每行一个任务，行内状态徽标、类型、输入摘要、时间。
3. **空态与总结**：无任务时说明「当前没有排队或运行中的任务」；不显示假的进度或示例任务。

排队位置只对 `queued` 显示，且只在权威队列顺序可判定时显示；位置变化由事件推送更新，不做本地猜测。**不显示预计等待时长**——设计文档明确不承诺不准确的等待时长。

### 3.2 每任务可观察信息

| 信息 | 说明 |
|---|---|
| 类型与角色 | 整理／修改／三角色试跑／今日建议／模型测试，及其固定角色 |
| 输入摘要 | 不可变输入的可读引用（原文片段、来源标识）；不显示凭据或秘密 |
| 配置修订 | 入队时固化的配置修订号；待执行期间改配置不影响已入队任务 |
| attempt 与 epoch | 当前尝试与实例标识，用于解释「晚到结果被拒」 |
| 占用的执行槽 | `running`/`cancelling` 显示 n/3；`cancelling` 的槽位在未确认退出前一直显示，不因取消而消失 |
| 槽号分配 | 领取时取 1..`agentConcurrency` 中**第一个未被 `running`+`cancelling` 占用的空闲槽**，不使用「占槽数 + 1」——中间槽释放后前者落到真空闲槽，后者会与仍占槽的任务双占 |
| 事件游标 | 该任务已收到的事件位置，供重连后判断是否漏事件 |
| 取消意图 | 是否存在未确认的取消意图 |

### 3.3 动作矩阵

| 状态 | 主操作 | 次操作 | 操作后的界面反馈 |
|---|---|---|---|
| `queued` | 取消 | 查看详情 | 行内立即转为 `cancelling`→`cancelled`；若与领取竞争，以权威结果为准并说明 |
| `running` | 取消 | 查看详情 | 先持久取消意图，行内显示 `cancelling`；确认退出后才终态 |
| `cancelling` | 无 | 查看详情 | 只读；说明「未确认退出前不释放执行槽」，徽标保留「槽 n/3」 |
| `failed` | 重试（可重试时）／重新提交 | 查看详情、检查配置 | 重试产生新 attempt；不可重试时指向配置修正 |
| `interrupted` | 重新提交 | 查看详情、核对外部结果 | 有外部副作用未知的先进入 `needs_review` 核对 |
| `needs_review` | 逐项核对 | 查看详情与回执 | 每项独立选择，见 §7 |
| `succeeded` | 查看结果 | 查看详情 | 进入候选／建议视图，不自动签收 |
| `cancelled` | 重新提交 | 查看详情 | 新任务新 ID，不继承旧 attempt |

取消排队任务是**确定**的：事务置 `cancelled`，调度器不得启动。与领取竞争必须有一个确定结果，界面按权威状态渲染，不显示中间猜测。

取消运行任务**不是撤销外部副作用**：已发生的 Bash、MCP、飞书发送不回收。文案必须说清「停止的是后续执行，已发生的结果需要你核对」。

## 4. 提交与幂等

### 4.1 提交动线

1. 用户在业务入口（文本整理、链接、试跑、今日建议、模型测试）发起，面板与业务入口共用同一任务事实。
2. 提交请求带**操作幂等键**（每次用户意图一个稳定键，重试不变）。
3. 提交成功才返回 `202 + taskId + state`；此时任务已落持久队列，界面立即显示为 `queued`，无论是否有空槽。
4. **满槽仍入 `queued`**。原「忙碌丢任务」／`409` 不作为普通提交契约，界面不出现「系统忙，请稍后再试」这类把已接收任务说成未接收的文案。

### 4.2 响应丢失与重复提交

| 情形 | 界面行为 |
|---|---|
| 同一操作 ID 重试（响应丢失、用户重复点击、刷新后重发） | 用同一操作 ID 查询，返回既有任务；不创建新任务。文案：「这条已经提交，显示的是同一个任务。」 |
| 同一操作 ID 对应不同输入 | 明确冲突，拒绝；文案：「同一操作对应了不同内容，已拒绝。请确认要提交哪一份。」 |
| 提交被明确拒绝（存储失败、输入无效） | 返回「未接收」，保留用户输入，不显示为已入队 |

重复提交防护在按钮层与查询层各一道：按钮在收到 `202` 后进入「已提交」禁用态并按操作 ID 可查；查询层用同一操作 ID 读回。任一层都不依赖「当前窗口是否持有 busy 状态」。

### 4.3 多客户端

后端保存任务与业务事实，**页面关闭不取消任务**。另一个标签页、另一台经代理访问的客户端提交的任务，本页按事件与快照看到同一队列。所有操作按 taskId 与预期版本定位；旧版本操作不覆盖新值，界面提示刷新。

## 5. 刷新、重连与事件补偿

| 情形 | 界面行为 |
|---|---|
| 正常刷新 | 取全量快照（带高水位游标），再从该游标订阅；不依赖 localStorage 重建队列 |
| SSE 短断线 | 按 `Last-Event-ID` 重放补发；连接状态显示「重连中」 |
| 游标超出留存或实例 epoch 变化 | 重新取全量快照；说明「已重新同步」 |
| 收到低于快照版本的旧事件 | 忽略；不用旧 `running` 覆盖新 `interrupted`。可见时可说明「这是旧事件，已忽略」 |
| 事件丢失 | 不丢任务：权威队列在持久存储，界面按快照与查询补齐 |

连接状态是面板的常驻元素（已连接／重连中／已用快照），但不阻塞业务操作。刷新后**排队位置、取消意图、待核对项必须原样重现**——它们都是持久事实，不是页面内存。

## 6. 取消语义

取消意图是持久事实，跨刷新、跨客户端、跨重启保留。

| 阶段 | 持久化顺序 | 界面约束 |
|---|---|---|
| 用户点取消 | 先记录取消意图，再停止 worker／工具树 | 立即显示 `cancelling`，不等待 |
| 停止中 | 保留取消意图与 attempt | 不释放执行槽，不显示已取消 |
| 确认进程树退出且无未知副作用 | 置 `cancelled` | 显示已取消与取消时间 |
| 无法确认退出或副作用未知 | 保留取消意图，转 `needs_review` | 说明「无法确认是否已停止或是否已产生外部结果」，进逐项核对 |

**执行槽的边界**：占槽保留到 `cancelling` 为止。转 `needs_review`（或 `cancelled`）时槽即释放——`needs_review` 是隔离不执行的暂停态，不占执行槽；潜在僵尸 worker 的处理属实例级「无法核实则暂停调度」，不由面板层保留槽位（权威 §5）。界面因此必须在转 `needs_review` 的同时给出逐项核对入口，否则该任务在演示/界面内无解。

转 `needs_review` 时必须生成（或关联到）一条持久核对项，使 §7.2 的三选一对该任务可执行；取消来源的核对项额外提供「用户明确取消」（由用户承担未知外部副作用风险、意图完成），以满足权威「无法核实时须用户明确选择重试/取消」。

重启时的恢复扫描覆盖全部未终态 attempt：有取消意图且能确认进程退出 → `cancelled`；能确认退出但副作用未知 → 保留取消意图并 `needs_review`；不能确认 → 保留取消意图并 `needs_review`，**不自动重入队**。

## 7. 失败、待核对与恢复核对

### 7.1 失败分类与重试

| 失败类别 | 界面 | 重试 |
|---|---|---|
| 可证为发送前／可安全重复的临时失败 | 失败原因 + 「输入已保留」 | 有界退避后自动重入队，界面显示重试次数与下次尝试 |
| 认证／配置错误 | 失败原因 + 指向设置的入口 | 停止重试；修正后重新提交 |
| 凭据引用不存在或无权读取 | 「执行时无法解析该凭据引用」+ 指向设置 | 停止重试；仅该任务不可执行，不影响其他环境引用 |
| 未知 MCP／飞书发送或 Bash 副作用 | 待核对 | 不自动重试；用户明确选择重试或取消 |

「已证可安全重复」的判定只能来自可信任务类型／工具记录；未知一律按待核对处理。界面不得把未知显示成失败或成功。

### 7.2 逐项核对（`needs_review`）

待核对项逐条列出，每条给明确选择，不允许「全部忽略」：

- **已确认完成**：用户已核对外部回执，任务转终态并保留回执引用。
- **标记失败**：确认真未生效，任务转 `failed`，可重新提交。
- **保留待核对**：暂不处理；说明「在核对前不会重新执行，也不会自动重发」。这一项**不解除风险**，恢复保持暂停；它只是**暂缓**，不是终局——拿到回执后必须仍能改选为已确认完成／标记失败／用户明确取消。
- **用户明确取消**（取消来源的核对项）：用户明确承担未知外部副作用的风险，取消意图完成；不自动重发。

每次选择都记录操作者与时间；**改选同样记录**，并从终态回到 `needs_review`、风险重新记为未解除。待核对项在面板中有独立计数与入口，不与失败混为一类。剩余项数按当前核对项实时计算（未选择 + 保留待核对），不缓存过期数字。

### 7.3 备份恢复与旧根激活

恢复与激活**不是原库重启**，界面必须说清数据回退边界：

1. **暂停**：停止接收新提交与调度，暂停定时收集、提醒／outbox 与补偿投递。界面显示「已暂停，正在校验恢复数据」。**「新提交」包含重新提交（resubmit）**：任何新建任务的入口（提交、重新提交、批量重试）在放行前一律拒绝，文案与提交按钮一致。
2. **校验**：校验恢复数据；失败则保持当前根不变并说明原因。
3. **隔离**：恢复出的未完成任务全部保留并隔离为待核对，取消意图仍保留。快照中的 `queued` 可能在备份后已完成外部操作，幂等提交键与 attempt fencing 不能证明它尚未发送。
4. **逐项核对**：按 §7.2 逐项选择；可证无副作用的只读任务可安全恢复，未知一律待核对。
5. **放行**：核对关闭前不恢复普通调度；不静默删除任务，不保证重建备份后发生的外部事实。**放行条件收敛为每项都是可解除风险的决定**：已确认完成、标记失败，或由用户明确重试/取消后转入的终态。只要还有一项停在「保留待核对」，恢复就保持暂停：暂停横幅保留并显示剩余项数，新任务提交、定时收集、提醒/outbox 与补偿投递继续暂停。界面不提供「全部忽略」这类一次性清空入口。

恢复界面固定展示：备份时间点、任务总数、待核对数量、可能重复的计划（定时收集、提醒、补偿投递），以及「无法核实时由你明确选择重试或取消」。**不能以原 `queued` 状态、旧成功回执或当前定时周期自动重发。**

已有根激活同样适用：更换到已有工作根、重新激活退役迁移源根、导入工作根副本时，除校验数据格式，还须证明它延续当前执行历史；无法证明或已知状态回退，一律进入上述核对流程。

## 8. 凭据与配置不可用

| 情形 | 界面 |
|---|---|
| 后端 provider 不可用（Linux 无钥匙串、macOS 服务无法解锁） | 明示系统凭据存储不可用与原因；允许环境引用凭据的模型／MCP 照常运行 |
| 引用不存在或无权读取 | 仅依赖该凭据的任务在执行时记为明确失败，输入保留、可重试；其他任务不受影响 |
| 配置修订被编辑或删除 | 已入队任务沿用入队时固化的修订，不失效、不静默改用新配置 |
| 秘密相关 | 界面不回读秘密、不显示秘密值、不保存无法兑现的引用；失败只说明引用名与原因 |

凭据状态与任务状态分开呈现：凭据不可用是**环境事实**，任务失败是**结果**。前者在设置页与受影响任务详情都要能到达。

## 9. 工作根目标与恢复入口

| 部署形态 | 界面 |
|---|---|
| 本机 Web | 由后端签发受限的 `workspace.manage` 能力：查看当前根、列出启动配置允许的目标 ID、提交选定 ID 的切换意图、按操作 ID 查询结果。页面不获得任意路径访问、进程启停或控制秘密 |
| Linux 固定根 | 根由服务启动配置确定；Web 显示逻辑位置与备份／导出入口，不提供切换任意服务器目录 |
| 备份恢复 | 业务会话下申请受限的备份创建、下载和恢复已校验备份；按 §7.3 状态机执行 |

切换流程：停收新任务 → 处理运行任务 → 关闭连接 → 校验目标 → 切换。响应丢失按操作 ID 读回，不盲目重复迁移。非法目标、旧版本、未授权会话、代理模式的根切换请求都被后端拒绝；界面显示拒绝原因，不提供「重试直到成功」的入口。

代理模式不签发根切换能力。即使客户端绕过 UI 或代理路由限制也不能调用——这是后端边界，界面只负责不诱导、不伪造成功。

## 10. 原生不可用能力与壳适配点

浏览器阶段不伪装原生能力。每个不可用能力有明确状态与入口，缺它不阻塞 Web 业务。

| 能力 | Web 阶段状态 | 入口 | 壳适配点 |
|---|---|---|---|
| 系统通知 | 不可用 | 应用内提醒中心照常工作；设置中标注「薄壳阶段提供系统通知」 | `NotificationSink` 新增 OS 通知渠道，不重写提醒业务 |
| 桌宠气泡 | 不可用 | 待确认／进展在应用内可见 | `PetSnapshot` 与语义事件；桌宠只消费快照，保留命中、穿透、拖动 |
| 托盘与全局快捷键 | 不可用 | 主窗与 ⌘K／Ctrl+K 快录可用 | 壳映射主窗、快录、托盘动作，不新增第二业务 store |
| 原生打开目录 | 不可用 | 显示逻辑路径与备份入口 | `HostCapabilities` 文件选择／打开 |
| 登录启动 | 不可用 | 设置中占位说明 | 壳阶段实现 |

`HostCapabilities` 在 Web 阶段返回不可用，界面据此禁用并说明，不导入 Tauri，不用伪造成功替代。业务组件经 HTTP/SSE 与后端交互；Tauri IPC 只限系统能力。断开页面不等于退出服务。

## 11. 文案规范

- **状态同时有文字与图标**；不用颜色单独传达状态。
- **说明保留了什麼**，不说空泛的「操作成功」：输入已保留、取消意图已记录、旧版本未覆盖新值。
- **不承诺等待时长**；排队只给位置。
- **区分「未确认」与「失败／成功」**：`cancelling` 与 `needs_review` 不用成功或失败的措辞。
- **外部副作用不可撤销**要明说，不暗示取消等于回滚。
- **恢复说明数据回退边界**：备份时间点之后的外部操作可能已发生。
- 不出现「系统忙，请稍后再试」这类把已接收任务说成未接收的文案；不出现模拟器式的假进度条。

示例（对齐生产既有语气）：

| 场景 | 文案 |
|---|---|
| 满槽提交 | 「已加入队列，排在第 4 位。前面 3 个完成后自动开始，关闭页面也会继续。」（含取消中占槽的满槽：位置按权威队列顺序给出） |
| 取消运行中 | 「已记录取消意图，正在停止。取消中仍占执行槽，未确认退出前不会释放，也不会显示已取消。」 |
| 取消排队 | 「已取消，这个任务不会执行。」 |
| 重复提交 | 「这条已经提交，显示的是同一个任务。」 |
| 旧事件 | 「这是旧事件，已忽略。当前状态以最新快照为准。」 |
| 凭据不可用 | 「执行时无法解析凭据引用「MODEL_KEY」。请到设置核对引用名；其他任务不受影响。」 |
| 待核对 | 「无法确认这个任务是否已产生外部结果。核对前不会重新执行，也不会自动重发。」 |
| 恢复暂停 | 「正在从备份恢复，已暂停新任务、定时收集与提醒。恢复点之后发生的外部操作可能已执行。」 |
| 保留待核对未解除 | 「仍有 N 项保留待核对，恢复保持暂停。每项都确认完成、标记失败或你明确重试/取消后才恢复普通调度。」 |
| 恢复期重新提交 | 「恢复未放行：已暂停新任务提交。请先完成逐项核对。」（与提交按钮同一闸门与文案） |
| 原生不可用 | 「系统通知在薄壳阶段提供。现在可在应用内提醒中心查看。」 |

## 12. 键盘焦点与无障碍

- 面板是单一 `region`，`aria-label` 说明用途；状态变化用 `role="status"`，失败与待核对用 `role="alert"`（与生产组件一致）。
- 任务行可聚焦，`Enter` 打开详情，`Esc` 关闭并焦点返回触发行。
- 取消按钮在行内，操作后焦点留在该行或其下一个任务行，不跳到页面顶部。
- 队列位置与状态变化通过 live region 播报，不依赖鼠标悬停。
- ⌘K／Ctrl+K 打开快速录入（沿用现有约定）：该组合由应用级入口处理，面板不 `preventDefault`、不捕获；面板内不得把它据为己有。
- 所有状态有文字，不只颜色；焦点可见样式沿用 `--action-focus`。
- 窄屏（≤760px）不降低可达性：行内操作变为整行宽度的堆叠按钮，live region 与弹层行为不变。

## 13. 窄屏适配

| 宽度 | 行为 |
|---|---|
| ≥1160px | 并发条 + 列表双列信息密度，详情右侧滑出 |
| 760–1160px | 单列，详情整页推入 |
| ≤760px | 卡片化任务行；操作堆叠为整行按钮；并发条吸顶；待核对计数固定可见；弹层全屏 |

窄屏不做功能裁剪：排队位置、取消、逐项核对、恢复流程全部可用。≤760px 时排队位置从行内右侧改为卡片内的位置标签（同色块、可读），不隐藏、不进二级详情。

## 14. 演示边界

`design/web-task-flow/` 只用合成数据：不连接模型、飞书、MCP、Bash、SQLite 或本机文件系统；状态切换由页面内定时器与脚本驱动，刷新复位；不用合成 IPC 代签真实服务。演示中的并发数、状态与文案对应本文语义；接口字段名、错误码取值与生产实现以契约冻结为准。
