本项是一个桌宠纵向能力，非批量：只细化一套表现、交互与宿主接线，可作为整体撤回；不是对多个业务对象做批量操作。窗口/IPC 改动按仓库 R3 准备，设计实质修订及交付须经 A/B 两面独立评审。设计阶段“不改代码”的历史授权已被后续明确实施授权取代，历史评审保留原范围。

## 3. 交互、姿态与生命周期

### 3.1 分开管理三类状态

不把所有状态塞进 idle/found/remind/done 四个名字。保持三类有界状态，由纯规则决定最终呈现：

| 维度 | 状态 | 所有者 |
|---|---|---|
| 窗口与交互 | hidden；可见时 free/left/right 与 expanded/collapsed；另有 dragging/menu-open | Rust 持有实际窗口与交互代次；前端消费确认后的状态 |
| 业务提示 | 当前根内 pendingCandidateCount；未来的真实待处理提醒快照 | Rust 从权威业务事实读取，不由动画计时器增减 |
| 短时表现 | idle、found 入场、done 致意；未来 remind 入场 | 前端纯规则与 CSS；不会写业务状态或显隐偏好 |

hidden 优先于所有几何及表现动作；dragging/menu-open 优先于自动收起和装饰动作。业务静态标记独立于短动作保留。一个窗口最多一个短动作，不建立补播队列；新的有效动作替换旧动作时提升播放代次，旧 timeout/animationend 无权清理新状态。

### 3.2 用户路径

| 当前状态与输入 | 目标行为 |
|---|---|
| 自由位置，鼠标悬停/移出 | 保持自由位置完整可见；不出现操作按钮 |
| 拖动本体 | 先取消收起与旧吸附；从完整姿态拖动，拖动中不播放装饰动画，不弹菜单 |
| 已确认松手且接近左右工作区边缘 | 吸附到当前目标屏的工作区边界；指针仍在角色上则保持展开，移出后半隐 |
| 半隐露出区域收到悬停 | 以原停靠边为锚点向屏内展开；不移动停靠高度，不抢键盘焦点 |
| 展开后指针离开，且未聚焦、未拖动、未打开菜单 | 短延迟后收回半隐；重新进入取消旧收起任务 |
| 右击角色或露出区域 | 保持当前停靠锚点，必要时展开，打开原生菜单；菜单存活期间禁止自动收起/穿透 |
| Esc/点击外部关闭菜单 | 关闭菜单，恢复命中判断；指针仍在角色或有键盘焦点则展开，否则按移出规则收起 |
| 菜单选择隐藏 | 宿主确认隐藏；撤销全部短动作、收起任务与可见期轮询；以后业务事件不 show/focus |
| 菜单栏手动显示 | 先确保可交互及位置可达，再读当前提示快照；不播放隐藏期间旧动作，按当前指针位置决定展开/半隐 |

原生菜单保留三个既有操作：“打开工作台”“快速录入”“隐藏班班”。单击不新增打开工作台行为，避免与拖动冲突；右键不触发拖动。聚焦角色后，菜单键/Shift+F10 可打开同一原生菜单；隐藏控件不留在 Tab 顺序中。已有主窗、快捷窗与菜单栏仍是替代入口。

初始交互参数：角色沿用约 112 逻辑像素；半隐保留约一半宽度，状态标记朝屏内；松手后距左右边界不超过 20 逻辑像素时吸附，向内拖离超过 32 逻辑像素后解除；移出延迟 450ms，收放过渡 180ms。它们是待验设计初值，不是测得的最优值；P0-S 验证后可在不改变 D1–D6 的前提下调节，并在记录中冻结最终值。减少动效时过渡直接完成。

### 3.3 动效与静态信息

- 完整可见、未被菜单/拖动占用且允许动效时，idle 只有轻微呼吸和间歇眨眼；本体不自动改变桌面位置。
- 本轮 found 表示“存在待确认候选”，不表示“签收成功”。新候选实际发布时，可在当时完整可见且可播放的窗口做一次举本子动作；基础标记一直保留到 pending 为零。签收成功只重算提示，不重新触发 found。
- done 只对本次新提交的“未完成→已完成”播放一次短致意。重新打开/删除使对应旧动作失效，失败、未知及幂等重试不制造致意。动作上限初值 1.5 秒，结束回到当前业务提示姿态而非无条件 idle。
- collapsed 始终使用静态姿态及朝屏内的标记；不循环动画，不因新事件展开。悬停后直接展示当前状态，不补播旧 found/done。
- remind 的视觉层保留提醒符号及静态样式；在 G3 权威提醒来源接通前，生产无提醒输入，不从截止时间自行推算、不展示演示数量。未来真正的未处理提醒持续到业务核销，短动画结束不清提醒。
- 工作模式、系统减少动态效果任一生效，或窗口隐藏、半隐、菜单打开、拖动、页面不可见时，停止装饰动画及其调度。保留业务静态标记、可访问名称与所有操作；不为提醒动画豁免系统偏好。
- 原生隐藏/重新显示信号是生命周期依据；visibilitychange 是补充。隐藏时取消而非积压短动作，重新显示重新读取权威状态。冷启动不恢复临时致意；petOnStartup 仍按既有规则决定初次显隐。

## 4. 业务事件与跨进程契约

### 4.1 触发矩阵

| 已有业务路径 | 静态状态变化 | 短动作 |
|---|---|---|
| 正式 extract 成功发布至少一个新候选 | 重读全根 pending 数量，进入 found | 可播放时按本次发布批次一次；零候选不播 |
| 候选编辑、签收、丢弃、应用修改预览 | 重读 pending，不从返回 todos 数量推算候选数 | 不重复发现动作 |
| 用户完成事项，新事务从未完成变为已完成 | 保留候选标记，更新当前业务事实 | 可播放时一次 done |
| 新建、普通编辑、重新打开、删除 | 不当作完成；重新打开/删除撤销相关旧致意 | 无 done |
| 试跑、模型连接测试、失败、取消、提交结果未知 | 不虚构正式候选或完成；业务成败以权威提交为准 | 无成功动画 |
| 重复 operationId/runId、延迟通知、启动/重显补读 | 恢复当前静态事实 | 不补播、不重复播放 |

业务提交成功后清单刷新失败，与事务失败分开处理；动画失败也不能把已提交的业务结果改报为失败或诱发再次保存。

### 4.2 只读快照与语义反馈

现有 todos-changed/organizer-changed 保留原用途。后续通过 store 层适配一个桌宠只读快照和明确语义反馈；以下是目标契约职责，名称在实施时与 Rust/TS 配对冻结：

| 通路 | 最小内容与规则 |
|---|---|
| 只读快照 | 不透明 workspaceEpoch、同根 stateRevision、pendingCandidateCount、已确认窗口可见/停靠状态；当前无真实提醒时不伪造字段值 |
| 业务失效通知 | 仅提示重读当前根状态；不携带资料原文、事项标题、凭据或本机路径 |
| 短反馈通知 | workspaceEpoch、commitRevision、playEpoch、feedbackId、kind、源实体引用与版本；仅在新提交成功边界产生，是领取提示而非可直接播放的指令 |
| 短反馈领取 | 固定 pet 请求指定 feedbackId 与所属根/播放代次；宿主核有效期和当前业务版本后至多发放一次，返回经核对的 stateRevision、playEpoch 与 remainingMs；空结果/失败直接丢弃，不影响业务 |
| 交互请求 | 仅固定 pet 的菜单/拖动/悬停等受限意图，宿主核对调用窗口和有限参数；不接受外部 window label、URL、脚本或任意资源路径 |
| 生命周期通知 | 宿主显隐、交互代次及可播放代次 playEpoch；隐藏/显示失败返回真实错误，不先把前端标成成功 |

约束：

1. Rust 在持锁业务读取/提交的同一排序域内确定 revision 和快照；不能给旧数据附新 revision。前端先订阅再初读，忽略旧根、旧 revision、卸载后的响应及旧交互代次。切根/重新初始化后更换 epoch，清空旧根反馈。
2. 新提交/幂等重放由宿主内部提交结果区分，可复用既有 operationId/runId；保持现有业务命令外部返回契约，不新增持久动画队列或数据库迁移。不做“先查是否重放、再单独提交”的竞态检查。
3. 短反馈按下方可播放代次与领取规则处理。宿主仅保留最近一个候选反馈，前端只有一个活动短动作及最多 256 项的会话去重集合；不建积压队列。宿主不因补读或领取重试重新产生反馈，重启后的初始化只恢复静态快照。
4. 候选静态标记依赖全根正式 pending 的权威计数。进入完整可见、打开菜单及重新显示时合并补读；可见期每 30 秒做一次有界校正，隐藏时停止该校正。静态查询失败时标明“状态暂不可确认”，不以零覆盖旧标记；这不是提醒送达时效承诺。
5. 动画与业务提示都不调用 show/set_focus。丢一次短反馈允许作为装饰性降级；持久提示丢通知可经快照校正。重复、未知、旧版本、旧根及异步乱序须有反例测试。

**可播放代次与期限。** playEpoch 由宿主单调递增，进入或离开 hidden、collapsed、menu-open、dragging、减少动效/页面不可见等播放阻挡边界时推进；换根同时更换 workspaceEpoch。前端观察到本地阻挡条件时立即撤销当前动作及未完成领取，不等待 IPC；重新允许播放要等宿主确认新的 playEpoch，不能沿用旧代次。业务提交与短反馈注册须保持因果顺序，记录提交所处的 playEpoch、commitRevision 及宿主单调时钟产生时刻；不得把异步 emit 时的最新代次倒填给旧提交。实现若不能在提交点可靠取该代次，可在操作开始时捕获并要求提交时仍相同，宁可丢装饰反馈，不跨代次补播。

反馈有效期从**新业务提交成功的宿主单调时刻**起计，最多 2 秒；登记/emit 迟到不重置起点，不能从消息到达或动画开始时重新计龄。事件负载不依赖跨进程可比的 Date.now/performance.now 时基；宿主领取时以自身单调时钟计算 remainingMs。前端记录领取请求发出至响应接收的本地单调耗时，从 remainingMs 中保守扣除整个往返时间；不为动画重新延长剩余期限，非正值即丢弃。由此通知或领取响应迟到均不能把过期反馈续期。

**播放前复核。** 收到通知先核当前根/playEpoch 和未消费 feedbackId；commitRevision 早于已知权威 revision 可保守丢弃。宿主在领取时核该反馈仍是当前单槽、未领取、同根/同 playEpoch、当前可播放且未过期，并重读源业务：done 必须仍是该事项版本的已完成且未删除状态；found 的发布批次仍须含待确认候选。重新打开、删除或源版本变化使旧反馈失效；查询失败/结果不确定即丢弃。复核后、发放前再查根/播放代次/feedbackId，仅在条件仍匹配时原子消费单槽；返回丢失允许漏一次致意，不重新发放。

前端在领取 await 返回后再次核存活、本地播放代次、根、playEpoch 与当前可播放条件，返回的 stateRevision 不得早于当前已知权威 revision。已处理较新撤销/删除通知或快照时不得播放旧完成；权威失效通知到达时先撤销关联动作和领取，再补读，不以补读成功为清理前提。尚未送达的跨进程变化不被声称即时可见，装饰动作仍受最长时限限制。活动动作到剩余期限或 1.5 秒上限即结束，animationend 只作补充。

这是一条固定 pet 的装饰反馈领取通路，不是持久确认/重试系统：只有临时单槽、无数据库迁移、无业务二次提交、无补播。旧根、旧 playEpoch、过期/已消费 ID、未知来源版本及畸形参数均拒绝；静态候选标记仍只靠权威快照，不依赖领取成功。

代码落点仍按现有架构：纯转换/优先级/代次规则放 src/domain；IPC/listen 与清理放 src/stores；SVG 与样式放 src/components、src/assets；窗口/菜单装配放 Rust app；权威候选查询及提交元信息由 Rust store 提供。Runtime 不直接驱动 pet，也不新增通用动画框架。

## 5. 原生窗口、吸附与找回

### 5.1 半隐机制与命中

选定优先验证的路线是：**宿主窗口保留在工作区内，角色向停靠边裁切/平移，展开向屏内进行，同时收窄实际命中区域**。不以把整个窗口移出屏幕作为默认机制，避免相邻屏继续显示“藏起”的部分或系统重排窗口。展开前后固定外侧停靠锚点，只有角色在窗内的表现变化，不能因尺寸变化引发反复 enter/leave。

透明并不等于穿透。CSS pointer-events 只改变 DOM 命中；set_ignore_cursor_events 是整窗开关。方案由 Rust 维持系统指针位置与角色可见区域的命中判断，恢复/关闭穿透，前端上报的几何必须受尺寸和状态约束，不能指定其他窗口。可见且需要穿透恢复时才运行单个有界检查循环，隐藏/退出即停止；不注册全局按键/鼠标监听，不记录用户移动轨迹，不申请输入监控或辅助功能权限。

P0-S 必须在当前单屏验证角色可见轮廓、露出唤醒带、既有姿态变化及裁切与原生命中的一致性；P1 对新动效资产继续做同屏原生回归，不从静态姿态外推动态命中。透明外部区域应可点击到底层应用；固定矩形或防抖包络不能作为透明区验收的替代。露出带要能反复唤出，且静态候选标记位于露出部分。不能开启整窗穿透后，仍只依赖该窗 mouseenter 来恢复；需要窗口外的系统指针位置读数。读数/同步失败时恢复可交互、停止自动收起，并保留菜单栏手动找回入口，不让角色永久失联。

命中循环频率与既有姿态的轮廓计算方式，在 P0-S 以当前单屏的真实输入和资源证据冻结；新动画姿态在P1继续验证，跨屏/混合缩放在P4-M补齐。不能先以粗矩形交付，再把透明区缺口写为通过。若轻量方案无法同时实现穿透与重入，暂停依赖步骤，提交替代技术方案评审；不得静默改成常驻不穿透的大矩形。

### 5.2 拖动结束与屏幕坐标

- 吸附只发生于**已证实松手之后**。锁定的 Tauri WindowEvent 没有窗口 drag-end；DragDrop 是内容拖放，不能混用。start_dragging 发送原生拖动请求，其返回不等于松手；Moved 短暂停止也可能是用户按住不动。
- P0-S 先验证原生拖动的可靠结束/取消信号。若固定依赖不能提供，再评估 WebView pointer capture 驱动受限位移的路线；当前单屏实测移出原窗、快速拖动、失焦与取消，跨屏拖动实测归P4-M。两路在单屏都不可靠时，不进入吸附实施，不以猜测超时替代。
- 每次新拖动提升交互代次，取消旧吸附/收起；程序 set_position 产生的 Moved 只能更新几何，不再次触发吸附。半隐状态拖动前恢复完整本体，松手远离边界保持自由完整状态。
- 使用显示器工作区而非整屏尺寸，排除菜单栏/Dock。桌面坐标允许负数。统一采用桌面逻辑坐标计算吸附和命中，再按各 API 的坐标口径转换；不能把不同 API 的 PhysicalPosition 直接相减。
- 本地锁定源码表明，macOS 光标位置使用主屏缩放，窗口位置使用当前窗口缩放，工作区按各屏缩放。P0-S 记录转换公式/来源并核当前同屏坐标；混合缩放、负坐标屏的真实核对归P4-M。类型同名不足以证明口径相同，几何负例不替代真实多屏证据。

### 5.3 工作区边缘与恢复

目标屏按松手时角色中心所在工作区确定；位于工作区间隙则取最近可达工作区；距离相同保留拖动前目标屏。只有当前屏工作区左右边界参与半隐吸附；屏间接缝也是各屏工作区的边界，按屏内裁切处理，不能把角色移动到邻屏。上下与角落只做工作区内钳制；极窄工作区不能容纳角色时，先保持完整可交互，不强制收起。

启动、重新显示、屏幕缩放变化、唤醒及显示器配置变化后，重新枚举工作区并检查可达性；不能只依赖窗口 Moved/ScaleFactorChanged 便声称覆盖拔屏。P0-S 验证当前同屏启动、显隐与工作区校正。固定版本没有显示器拔插的 WindowEvent，真实缩放/配置变化探测及拔屏恢复归P4-M，缺硬件时保持未验。可见期的原生检查循环合并低频屏幕变化检查，隐藏时不持续轮询，显示前再校正。

原屏消失或几何无效时，清除失效停靠与收起任务，把可见 pet 完整放回当前有效工作区。主动 hidden 不因拔屏/唤醒重新显示，只记录需要在下次手动显示时恢复。无可用显示器时保留状态、等待重显检查，不用无限 set_position 重试。普通位置恢复不能重写启动显宠偏好；冷启动持久化按既有 S4 后续项单独交付。

### 5.4 原生菜单及失败恢复

菜单只在用户请求时打开；原生菜单负责边缘放置、键盘导航和 Esc。宿主复用固定动作白名单及三个既有入口，不由前端拼接任意动作。菜单实例和打开代次有单一所有者，关闭/取消/卸载均清理；不能只监听“选中了菜单项”就假定 Esc/点外部会发相同事件。原生 popup 的关闭可观测性列入 P0-S。

菜单存活时保持角色可交互、暂停自动收起与装饰动画；菜单关闭后核对实际指针/焦点再恢复。工作台/快捷窗操作失败，保留当前桌宠并给静态错误；隐藏失败不假装已经隐藏。后台读取失败只更新状态可信度，不因报错自动展开、显示隐藏窗口或打开主窗。

## 6. 渲染方案与技术取舍

| 技术选择 | 选定路线与理由 | 放弃/延后的路线及代价 |
|---|---|---|
| T1 角色动效 | 分层内联 SVG＋CSS transform/opacity；复用现有形状、命名身体/双眼/本子/标记分组，用单一暂停入口 | 外链 img 只能直接动整体；CSS＋motion-v 双编排增加清理负担；Lottie/Rive 没有现成资产且需新依赖/管线 |
| T2 半隐 | 屏内裁切/平移＋同步命中；先过 P0-S，跨屏实测留P4-M | 整窗屏外定位有系统约束及接缝风险；完整贴边已被 D1 否决，不作为技术降级默认值 |
| T3 菜单 | Rust 原生菜单，D2 已去掉 hover 快捷栏 | 自绘菜单要自行实现边缘翻转、焦点与键盘；额外菜单窗口增加生命周期和命中面 |
| T4 业务通路 | 只读权威快照＋新提交语义反馈；持久提示与装饰动作分离 | 对通用 changed 事件猜动作会误报；只用一次性 emit 无法恢复提示；新建持久动画队列没有必要 |
| T5 窗口能力 | Rust 固定 pet 目标；沿用 stores 归口 | 不默认给全部前端窗口新增位置/穿透权限；如后续确需扩 capability，重新过边界评审 |

T1–T5 来自本轮两个全新上下文的技术比较，并经作者按现有约束裁决；选项证据与评审发现见本轮记录。产品体验由 D1–D6 确定，技术选择不能覆盖它们。

SVG 调整采用 WebKit 可验的变换与明确 transform-origin/transform-box，不做路径形变或重新设计品牌。身体、眼睛、附加图案拆层以便独立控制；应用其他位置仍可消费原静态资产。CSS 时间线停止后必须落在完整的静态姿态，不能依赖 animationend 才清状态。若以后引入 JS/WAAPI 控制器，显式 cancel/stop 与代次检查不可省略。

对[原调研](../reviews/pet-animation-research-20261104.md)的限定：保留历史原文，本项不将其“低风险”“空闲开销最低”“减少动效天然覆盖”等判断当成实测。已安装 motion-v 默认 reducedMotion 为 never，useAnimate 的卸载清理不能替代原生隐藏清理；选 CSS 也仍需资源测量。Rive Canvas 与 WebGL 是不同运行时，不能无条件称任一路线性能最好。现有 Rust 可调用窗口 API，不必然需要扩大前端 capability。工作模式保留提醒的静态语义，不要求豁免提醒动画。

## 7. 菜单栏资产

从现有班班标志派生专用透明底单色图形，保留能在小尺寸辨识的脸部/马甲特征。不能直接把带实心底板的 app-icon.svg 标成 template，否则主要显示底板剪影；也不能只把彩色实心区域统一填黑而失去内部辨识。

目标提供适合约 18pt 菜单栏的 1×/2×图形，保留可重建的生产 SVG 来源与小 PNG，编译期嵌入并启用 icon_as_template，不引入运行时 SVG 解码器或新的生产依赖。不改 Dock/App 图标、identifier 或 s0-runtime。普通与专用包共用这份窄资产，专用包仍保留原路由、隐藏探针窗口和隔离规则，不因此启用生产桌宠。

验收浅色、深色、选中三种菜单栏状态及 Retina/non-Retina 缩放，图形边缘清晰、背景透明、无蓝方块，原菜单行为正常；编译可用不是资产辨识度已验。

| P3 菜单栏与单屏收口 | 普通/专用包统一单色标志，完成当前设备上的真实包与资源证据 | 可与 P1/P2 分别验证但不并行修改同一宿主文件；独立交付复核后，稳定版本运行全量门禁；硬件未具备项保持开放 |
| P4-M 多屏与最终验收 | 混合缩放、负坐标屏、接缝/拔屏、1×显示及其余安装/全屏等既有矩阵 | 需具备相应真实硬件/环境；逐项满足V8/V10/V11及产品验收后才讨论整体关闭/发布，不能用几何替身或先前单屏证据替代 |

命令来源为当前 package.json，实施时需重新核对：聚焦可复用 npm run test:s1-domain、test:desktop-host、test:desktop-controls；新增领域测试应进入对应既有脚本及完整 check，脚本名保持稳定。前端跑 typecheck/build，Rust 跑 check:rust，新增文件跑 check:structure，文档跑 check:docs；最终实现收口必须有一次独立完整 npm run check。脚本/fixture 必须在干净检出中可取得，不能依赖忽略的 build 目录。原生测试须另外取证，完整门禁不能替代它。

失败策略：装饰动画/反馈失败保留静态姿态及业务事实；命中或屏幕转换不可信时停止自动收起，恢复可交互并允许菜单栏找回；hidden 始终优先。基线所需的半隐/穿透长期不能成立时，保持未验、返回方案调整，不自动降级成 owner 已否决的完整贴边或恢复按钮栏。

本项不改数据库、迁移、应用身份、依赖或持久显隐偏好；后续代码恢复采用回退本项有限改动及恢复旧图标/表现入口，不回滚或清空事项数据。不得为获取新鲜基线去 stash/reset 用户工作。真实环境、系统设置、发布/提交/推送仍需对应授权。

### 9.1 正式前端的隔离单屏验收载体

技术比较选定独立 `pet-ui-verification` feature及required-feature example，使用crate内窄桥接复用生产desktop装配/IPC，不启用或改变S33验收包的生产桌面禁用规则，也不从普通app::run启动验收。验收模块放diagnostics，可作为app的feature-gated子模块；生产路径不反向依赖诊断。以下是实施前需满足的载体契约：

| 边界 | 选定规则及验证 |
|---|---|
| 启动准入 | example只接受固定私有标志；普通包遇该标志在Builder/真实appData前拒绝，误将验收feature编入普通main时也拒绝普通启动。新验收入口不与S33两种验收feature混用；冲突在开根前拒绝 |
| 全新临时根 | 进程内部生成nonce，在canonical临时父目录中独占新建0700所有权目录；不从前端、CLI或环境接收appData/workspace路径。首次Store使用不消费bootstrap路由的空存储/固定根初始化入口；若application目录已存在bootstrap则拒绝。显式initialize(Some(owned/workspace),UTC)后保留该AppStore，与guard一起交给LocalState，不丢弃后重开，不reopen、不升级已有验收根 |
| 身份守卫 | 复用既有verification_root的持有FD、nonce/marker、目录inode模式，新增pet-only新建模式。初始化后固定该会话DB inode；每次LocalState.access先验证，bootstrap只作一致性检查、不能决定打开哪个根。pet-only必须使用预先初始化的缓存Store，缓存缺失/失效时拒绝，禁止落入普通AppStore::open的bootstrap惰性开库分支。目录/DB/指针被替换、缺失或无法确认时拒绝、不修复、不切根；补“校验后、消费前稳定替换指针”的合成反例，断言另一个合成根未被打开/修改，缓存缺失也不重开 |
| 资产与WebView | prepare先执行既有npm run build，将实际dist复制到隔离build资产树，只在副本加入受跟踪console HTML/JS。仅为example编译子进程提供固定TAURI_CONFIG（devUrl=null、frontendDist=复制树、windows=[]），拒绝预存TAURI_CONFIG；生产identifier/CSP/capability不改。main console及复用setup创建的pet/quick均在创建时仅该验收feature启用incognito |
| IPC白名单 | 只注册生产desktop及本项pet命令、真实QuickEntry必需的workspace_info/read_application_settings/create_todo，以及有限console场景。console校验main label及本地固定console URL，参数有限enum/拒未知字段。没有任意SQL/路径/脚本/window目标或直接pet状态参数 |
| 业务事实来源 | 合成候选经begin_import→publish_candidates，签收/丢弃及完成/撤销走正式store API；不运行模型。发布和完成必须走与生产相同的新提交/语义反馈接缝；console不得直接emit found/done或篡改pet快照。计数来自实际临时SQLite，不从测试按钮次数推算 |
| 能力排除 | 不注册模型、MCP、凭据、initialize_workspace、目录打开、run_s0_probes或autostart/notification/dialog等无关插件。只保留生产setup所需global-shortcut插件，注册失败沿既有可见降级，不修改系统设置 |
| 生命周期与留存 | 监督先于context/根/窗口建立，独立于轮询停止和主循环响应；本轮载体最长30分钟，仅终止自身。正常退出先停止命中/装饰调度并释放SQLite/守卫；超时不计通过。临时合成数据默认保留供复核；只有确认PID已退出、锁释放且nonce/inode归属仍一致，才可在对应授权下清理该根，不扩大删除范围 |
| 证据及包排除 | 原始NDJSON/截图/包/哈希进独立build目录，仓库只收精选记录。验收后用普通构建和普通入口负例检查console资源/私有场景标记不进正常包；现有只针对S33的排除检查不能替代本项新增负例 |

覆盖范围限定为真实PetWindow、真实桌面IPC和合成业务事实：main console只能证明“打开工作台”的固定目标窗动作，不证明真实Workbench内容；QuickEntry可验证临时根真实手工录入。真正生产根、真实模型/渠道、安装/全屏/多屏、未具备的硬件矩阵保持开放。载体通过也不改变正常包默认显隐、工作模式或数据权限。

## 10. 技术证据与开放项

源码出处按 §1.1 基点复核，锁定依赖来自 package-lock.json/Cargo.lock；本机缓存路径不作为干净检出的前提：

- Tauri 2.11.6：window::Monitor::work_area、Window::cursor_position/set_ignore_cursor_events/start_dragging/popup_menu，app::WindowEvent、tray::TrayIconBuilder::icon_as_template；参考[固定版窗口 API](https://docs.rs/tauri/2.11.6/tauri/window/struct.Window.html)、[固定版事件](https://docs.rs/tauri/2.11.6/tauri/enum.WindowEvent.html)、[固定版托盘](https://docs.rs/tauri/2.11.6/tauri/tray/struct.TrayIconBuilder.html)。
- 本地锁定 tauri-runtime-wry 2.11.4 的 start_dragging 发送 DragWindow；tao 0.35.3 的 macOS util::cursor_position/Window::outer_position 与 runtime-wry 的 monitor::work_area 使用上述不同缩放口径。P0-S 按这些实现核公式和当前同屏结果，P4-M 验真实跨屏结果，不能直接照搬最新版 API 示例。
- motion-v 2.9.0 的 motion-config/context 默认 reducedMotion=never，use-animate 仅在卸载时自动 stop；[MotionConfig 文档](https://motion.dev/docs/vue-motion-config)不构成应用隐藏清理保证。
- [Rive 官方运行时区别](https://rive.app/docs/runtimes/web/canvas-vs-webgl)只用于纠正调研选型表的运行时混同；本设计不引入 Rive。性能、包体与兼容性均须以本项目探针为准。

未解决的是技术假设 H1 拖动可靠结束/取消信号、H2 命中与穿透恢复、H3 混合缩放/工作区及配置变化、H4 原生菜单关闭生命周期、H5 bundle 透明/隐藏资源及小尺寸动效/图标辨识。单屏相关项归P0-S/单屏验收，多屏与硬件缺口归P4-M；都有 §8/§9 对应验证和停止条件，不是已实现或已验证项。目前没有未获确认的产品方向；若探针要求改变 D1–D7、权限/依赖/数据边界或验收，重新交由 owner 决定。
