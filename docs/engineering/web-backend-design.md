## 2. 目标装配与职责

```text
Vue Web（浏览器 / 后续 Tauri WebView，同一业务 UI）
  └─ HTTP 命令/查询 + SSE 状态通知
Node/TypeScript 后端（单实例、单工作根、唯一正常业务写入方）
  ├─ API / 会话 / 请求运行时校验
  ├─ 事项/候选/来源/进展/签收/提醒/日报/配置
  ├─ SQLite 持久队列 + 调度器（默认 3 个智能体执行槽）
  ├─ Pi worker / MCP / Skills / lark-cli 适配
  ├─ CredentialProvider（随后端 OS 选择）
  └─ Rust 原生存储适配（连接、短事务、文件身份、根锁）
后续薄壳
  └─ 窗口/桌宠/托盘/通知/快捷键/登录启动/后端生命周期
```

Node 后端保留 Pi 固定源码与现有 Vue 品牌组件，业务事务从 Tauri 中移出；Rust 适配独立于 Tauri，在 macOS 与 Linux 各自构建。适配统一拥有业务连接与根锁，暴露异步调用的存储接口，不由 `node:sqlite` 再按路径重开业务库。数据库在独立执行上下文处理；HTTP/SSE 不因同步 SQL 阻塞，模型和工具执行期间不持有写事务。

旧数据格式无需兼容，但文件安全仍保留：已有业务库打开拒绝符号链接、意外创建与身份变化，检查根/数据库及 WAL 侧文件的权限、链接数和文件身份；新根初始化使用独立的显式创建流程。连接与根锁同生命周期，任何失败停止读写，不能把“缺库自动新建”伪装成成功恢复。

新后端不要求沿用 v1–v5 schema 或所有旧 IPC 名称；可复用仍合适的规则和测试。具体 schema、生产依赖和目录守卫调整在实施切片列出变更后按仓库约定授权。本轮只写设计，不新增依赖、DDL、迁移文件或生产入口。

工作根位于后端主机：本机模式可在后端允许目录内选择；代理部署的浏览器不能选择访问者电脑上的路径，也不能通过“打开目录”执行服务器原生命令。Linux 根由服务启动配置确定，Web 显示逻辑位置、备份/导出入口；切换必须停收新任务、处理运行任务、关闭连接后校验目标。单根锁防多个后端误开同根，不承担旧版兼容功能。

**本机 Web 工作根管理的授权闭环**：本机配对会话由后端签发受限的 `workspace.manage` 能力，仅允许查看当前根、列出启动配置允许的目标 ID、提交选定 ID 的切换意图及查询其结果；能力不由页面自行声明，也不授予任意路径访问、进程启停或控制秘密。后端校验会话能力、local 模式、目标白名单与预期版本，再以持久操作 ID 执行停止调度/处理任务/一致性迁移/校验/切换，并返回明确成功、失败或待核对状态；响应丢失按操作 ID 读回，不盲目重复迁移。允许目录由主机启动配置/可信本地控制端确定，页面不能自行扩大。

代理模式不签发根切换能力，后端拒绝此类请求，即使客户端绕过 UI 或代理路由限制也不能调用。Linux 固定根的变更由服务操作者完成；浏览器仍能在业务会话下申请受限的备份创建、下载和恢复已校验备份，后端执行其状态机与副作用核对。这些是受限数据管理业务，不等于持有宿主 control token；服务发现、退出及任意主机管理仍只属于独立控制通道。

## 3. 本机与反向代理部署

### 本机默认模式

后端监听 `127.0.0.1`，同源提供 Web 静态资源、业务 API 与 SSE。首次启动在终端分开显示地址与一次性配对码，码仅通过 POST 请求体交换短时会话，单次有效、5–10 分钟过期、失败限速；不进入 URL、runtime metadata 或日志。写请求检查精确 Host/Origin 与 CSRF，cookie 为 HttpOnly、SameSite=Strict、限制 Path、不设 Domain；HTTP 回环不依赖 Secure cookie。页面刷新、SSE 重连均校验会话，退出可撤销会话。

### 主机代理模式

仍由同机反向代理访问回环后端，浏览器使用一个 HTTPS 公共 origin。该模式必须显式配置 `publicOrigin`、允许的代理来源以及代理到后端的秘密头；默认不因收到 `X-Forwarded-*` 就切换信任模式。代理需覆盖静态资源、API、SSE 的访问认证（例如部署方已有网关认证）；这不新增 Sidekick 团队账号体系。

- 代理清除客户端自带的身份/转发/秘密头，再添加服务端配置的代理秘密；后端对秘密和来源同时核验，秘密缺失时拒绝代理模式请求。秘密以环境引用提供、不进配置、浏览器或日志。
- 后端只对可信代理接受 public origin/HTTPS 语义；校验完整外部 Host/Origin，cookie 强制 Secure。客户端同样经带外配对与业务会话访问，代理认证不能代替业务写入的 CSRF 校验。
- 宿主控制接口（发现、退出、任意主机管理）使用独立控制通道与 control token，不放进代理暴露的业务路由。受限工作根/备份业务按 §2 的会话能力与状态机执行；代理公开 HTTP 服务不能关停宿主或获得控制秘密。
- SSE 关闭代理缓冲与缓存，配置心跳、读取超时与会话过期后的断开/重新认证；代理模式须实测代理认证、流式到达、重连与未认证拒绝。仅加 `proxy_pass` 不构成部署验收。
- WAL 数据库位于后端本机磁盘，不能放 NFS/共享网络卷；同一数据库不部署多个服务副本。容器跨网络命名空间的组网需独立设计，不擅自把监听改为公网地址。

上述是部署目标，当前没有 Linux 安装、代理配置或 TLS/认证实测证据。开发验证使用合成凭据与临时根，真实代理上线另行授权。

## 4. 凭据属于后端主机，不属于表现形式

| 后端环境 | 默认能力 | 页面表现 |
|---|---|---|
| macOS 本机 Web 或桌面壳 | 环境引用；可用时使用 macOS Keychain | 返回 provider 能力与可用性，不回读秘密 |
| Linux 服务 | 环境变量引用；默认没有 macOS Keychain | 明示系统凭据存储不可用；允许环境引用模型/MCP 照常运行 |
| 其他 OS/未来安全存储 | 通过 provider 接口增补，先验证再宣称支持 | 由能力返回值驱动，不按“浏览器/桌面”硬编码 |

Linux 不模拟 macOS 钥匙串，也不自动降级成明文凭据文件；若以后使用 Secret Service/vault，另列依赖、运维与恢复契约。无桌面会话的 macOS 服务也可能无法解锁 Keychain，须显式报错，不仅检查 OS 名称。引用不存在或无权读取时，只影响依赖该凭据的任务；前端禁止保存无法兑现的钥匙串引用。

任务入队只保存配置修订与凭据引用，秘密到执行前由后端解析，按 run 私有 stdin/环境注入 worker；不写入队列、SQLite、argv、配置、日志或 SSE。队列等待期间凭据可撤销，执行时解析失败记为明确失败并保留可重试输入，不无限占槽。不同 run 的 cwd、凭据、配置/技能快照、日志与取消句柄隔离；Bash 仍以服务 OS 用户权限执行，无沙箱或逐工具审批承诺。部署到 Linux 后，Bash/MCP/文件访问都发生在服务器上，不能读访问者电脑；该服务不能向不可信网络用户开放。

## 5. SQLite 持久任务队列

SQLite 足以作为当前**单后端实例**的队列与状态来源；并发 3 指模型/工具执行并发，数据库写事务仍短暂串行。先不引入 Redis、分布式 worker 或 Pi durable；容量以实际延迟、写锁等待与排队年龄验证，不承诺未测的吞吐。

### 提交与调度

- 一个实例级设置 `agentConcurrency`，默认 3，必须为正整数。上调后补发空槽；下调不杀正在执行的任务，待其自然退出后再满足新上限。
- 模型任务（整理、修改、三角色试跑、今日建议及模型测试）共用执行槽；MCP 连接诊断等非模型工作另设有界资源控制，不能绕过每任务取消、cwd 与清理归属。
- `POST /api/tasks` 带幂等操作 ID。一个短事务保存任务、输入引用、角色/配置修订、提交顺序与初始事件；提交成功才返回 `202 + taskId + state`。响应丢失时用同一操作 ID 查询/重试，不能再次创建任务。满槽仍入 `queued`，原 `RUNTIME_BUSY`/409 不再作为普通提交契约。
- 入队时保留不可变输入及非秘密配置快照（或可读回的不可变修订）；待执行期间编辑/删除配置不能让旧任务引用失效或静默采用新配置。技能内容按已定义的任务快照规则固定；凭据仍只存引用、执行前解析。
- 存储失败或输入无效时返回明确“未接收”；同操作 ID 对应不同输入返回冲突。不承诺磁盘故障下无限接收，但已经 ACK 的 queued 任务不能因排队满、页面关闭或服务重启被静默丢弃。
- 就绪任务按持久提交顺序 FIFO 领取；延迟重试未到时不阻塞后续就绪任务。定时触发使用来源/周期幂等键，合并尚未完成的同一周期任务，不让轮询无限重复灌队列。领取用事务原子检查状态并写入 `attemptId`/实例 epoch，执行不在事务内进行。

### 持久状态与失败语义

以下是待实施的数据契约，表名与 DDL 在对应切片定案。逻辑字段包含 taskId、操作幂等键、类型/角色、输入引用、配置修订、state、attemptId、owner epoch、进度、取消意图、nextAttemptAt、结果引用和有序事件游标。业务结果、任务终态及可见事件在同一事务提交，签收仍单独由用户确认，不能把 task success 当正式事项已签收。

> **2026-11-07 定案（已授权实施中）**：新库为独立 web-backend/1 lineage（application_id `0x57424b31`），路径 `<workspaceRoot>/data/web-backend.sqlite`，11 表并采纳 `task_result_payloads` 承载 `result://<attemptId>/<name>` 结果负载；每任务至多一个未结束 attempt 由部分唯一索引在 schema 层强制；迁移进度以 `PRAGMA user_version` 为权威、`schema_meta.schema_version` 为同事务镜像，不符显式拒绝。旧库与既有 001–005 不动，不做历史迁移或兼容桥。最终 DDL 以 `docs/reviews/web-foundation-integration-schema-authorization-20261107.md`（随实现交付合入）及实施计划登记为准；实现未验证、未合入前，本节其余内容仍是设计而非现状。

| 状态/动作 | 规则 |
|---|---|
| `queued` → `running` | 原子领取并占一个槽，每个 attempt 只启动一次 worker；查询能看到队列顺序 |
| queued 取消 | 事务置 `cancelled`，调度器不得启动；与领取竞争必须有一个确定结果 |
| running 取消 | 先持久记录 `cancelling`/取消意图，再停止 worker/工具树；未确认退出不释放槽，不显示已取消 |
| 正常结束 | `succeeded` / `failed` / `cancelled`；结果仅被当前 attempt 接受，晚到结果不得覆盖新尝试或已取消任务 |
| 后端重启 | queued 保留；先确认旧 worker 已停再恢复执行槽。上次 running 记为 `interrupted`；有外部副作用结果不明则 `needs_review`，保留输入与已知回执，禁止自动重放 |
| 重启时有取消意图 | 恢复扫描全部未终态 attempt，保留 `cancelling`/取消意图；确认所属进程树退出且无副作用未知后才置 `cancelled`。未知则保留取消意图与 `needs_review`，不得自动重入队 |
| 重试 | 已证为发送前/可安全重复的临时失败才有界退避重入队；认证/配置错误停止重试；未知 MCP/飞书发送或 Bash 副作用需核对或用户明确重试 |

worker 以父管道/guardian 检测宿主消失；下一实例拿根锁不等于旧 worker 已停。启动前清理/核实上次实例所属进程，无法核实则暂停调度并显示原因，避免默认 3 实际超发。正常关停先停止新提交与调度、保留队列，再取消/等待运行任务并 reap，最后关库释放锁。无需旧版回退桥，也不能忽略进程清理与任务证据。

**备份恢复不是原库重启**。恢复旧快照会倒退任务/投递回执；快照中的 queued 可能在备份后已完成外部操作，幂等提交键和 attempt fencing 不能证明它尚未发送。恢复使用独立入口与持久恢复标记：先停提交/调度并确认旧进程树退出，再校验恢复数据；恢复出的未完成任务全部保留并隔离为待核对，取消意图仍保留。定时收集、提醒/outbox 与补偿投递同时暂停，重启服务不能绕过恢复标记重新触发。

恢复界面说明数据回退边界，展示任务与可能重复的计划；逐项核对可验证的外部回执后才能放行。无法核实时须用户明确选择重试/取消，不能以原 queued 状态、旧成功回执或当前定时周期自动重发。对可证无副作用的只读任务可安全恢复，其判定须由可信任务类型/工具记录证明；未知一律保留待核对。恢复流程关闭前不得恢复普通调度，不静默删除任务，也不保证能重建备份后发生的外部事实。

**已有根激活同样适用恢复边界**：更换到已有工作根、重新激活退役迁移源根或导入工作根副本时，除校验数据格式，还须证明它延续当前执行历史。无法证明连续性或已知发生状态回退，一律进入上述持久恢复核对流程，暂停任务、定时/提醒/outbox，保留取消意图与全部任务；不得凭根锁可获取、格式合法或 queued 状态自动调度。正常原库重启须能核实当前活动根身份与执行历史；操作者手工回滚文件/磁盘快照须使用显式恢复入口，不承诺自动发现任意绕过产品入口的文件替换。验收覆盖 A→B 迁移、B 发生外部操作、再激活保留的 A 时不重发。

### 多客户端与事件补偿

后端保存任务与业务事实，页面关闭不取消任务。前端显示排队/运行/取消中/失败及可重试状态；服务返回队列位置，不承诺不准确的等待时长。所有操作按 taskId 与预期版本定位，不依赖发起窗口持有全局 busy 状态。

SSE 只通知已经提交的变化：事件附实例 epoch、递增游标、对象版本。短断线按 `Last-Event-ID` 重放；游标超出留存或实例变化时取带高水位游标的全量快照，再从该游标订阅。快照与订阅间的变化必须可补发；低于快照版本的旧事件忽略，不能用旧 running 覆盖新 interrupted。SSE 留存可短期有界，权威队列与业务状态在 SQLite；事件丢失不能丢任务。

## 6. 薄壳先定接口，Web 验收后接线

| 先设计的接口 | Web 阶段 | 薄壳阶段 |
|---|---|---|
| `HostCapabilities` | 系统通知、文件选择/打开、全局快捷键等不可用时返回不可用，不导入 Tauri | 在单一平台适配入口实现相应能力 |
| `PetSnapshot` / 语义事件 | 后端提供未读/待确认/提醒/完成事实，Web 可检验 payload/版本/重连 | 桌宠只消费快照与事件，保留命中、穿透、拖动等原生行为 |
| `NotificationSink` | 应用内/飞书投递，后端调度与投递回执完整验收 | 新增 OS 通知与桌宠渠道，不重写提醒业务 |
| `BackendConnection` | 本地启动/服务管理器拥有后端；断开页面不等于退出服务 | 壳可拥有随包后端或显式连接既有实例；区分 owned/attached，attached 退出不得杀服务 |
| 窗口与导航意图 | 业务只表达打开事项/录入/查看日报 | 壳映射主窗、快录、托盘动作，不新增第二业务 store |

业务组件经 HTTP/SSE 与后端交互；Tauri IPC 限于系统能力。系统能力缺失不应使浏览器业务不可用，也不能用伪造成功替代；目录权限、文件导出使用浏览器/服务支持的入口。WebView 跨源会话/CORS/CSP、连接所有权与退出、桌宠事件协议在设计期及窄探针验证，正式壳层代码和原生 UI 仍排在 Web 业务验收之后。未来接入不承诺“零调整”，但不得重划核心业务所有权。

## 7. 验证与停止条件

| 可达威胁/故障 | 控制边界与失败行为 |
|---|---|
| 外站诱导本机浏览器提交任务，或代理客户端伪造转发头 | API 会话与 CSRF、精确 origin、可信代理秘密验证；不合格请求不得入队/启动 worker |
| 普通业务会话请求退出服务/读取凭据，页面脚本取得控制权限 | 控制通道不暴露在业务代理，控制秘密不交页面；凭据只由后端 provider 解析，API/事件只返回引用/状态 |
| 多次提交、取消与晚到结果竞争或重启后重发工具 | 持久幂等键、领取/终态条件更新、attempt/epoch fencing 与副作用未知状态；不重复写结果/盲目重放 |
| 模型/来源文本指示 Bash 读服务器其他文件或发送秘密 | 模型输出按不可信业务输入校验，签收仍由可信业务 API 执行；通用 Bash 无沙箱的残余风险明确，服务限可信单用户，不能据此声称文件级隔离 |
| Linux 无钥匙串或 macOS 服务无法解锁，凭据被写进排队快照 | provider 能力检查、秘密不持久化；缺失引用显式失败，仅受影响任务不可执行 |

以上为设计控制，不是已部署防护。环境前置条件与剩余风险分别记录；真实服务的凭据、来源与进程权限验证不能由替身测试代签。

| 检查面 | 必需证据 |
|---|---|
| 并发与排队 | 提交 5 个受控任务，3 running/2 queued；调为 1/4；相同操作 ID 重试；取消/领取竞争；页面关闭/重启后队列仍在 |
| 崩溃与副作用 | 领取后/发工具后/结果提交前强退；旧 worker 未退出阻止调度；晚到结果被拒；未知工具结果不重放；数据库故障不返回已接收 |
| 数据与凭据 | 本机受限工作根切换、非法目标/旧版本/未授权会话拒绝、代理模式拒绝根切换、操作结果未知读回；多任务签收幂等/版本冲突、备份校验与恢复；“备份时 queued → 外部执行成功 → 恢复旧备份”及“A→B 执行外部操作→切回 A”均不再次执行，定时/提醒/outbox 保持暂停，取消意图跨恢复保留；每任务秘密/cwd隔离；macOS Keychain 可用/不可用、Linux env/缺失引用分别验证 |
| 部署边界 | 本机恶意 Origin/Host、未配对访问、代理伪造头、未认证 SSE、控制接口不可公开、SSE 缓冲关闭及事件快照补偿 |
| 完整业务 | 浏览器真实组装路径完成 G1–G3，包括飞书读取、持续跟踪、卡片回调、提醒与日报；受控服务/真实服务分层记账，缺失不能以原型代替 |
| 薄壳准备 | Web 无 Tauri 仍可跑全业务；系统能力适配契约可用；原生专属目标另验且不提前关闭 |

不兼容旧版是研发范围选择，不能推导为可清空真实用户根、静默忽略运行任务、跳过文件安全或泄露凭据。真实凭据、生产部署、schema/依赖变更、提交推送按仓库授权执行。原生适配跨 OS、代理会话、队列状态机与取消均须实施前独立评审；未验证时只能交付设计，不能声称已能运行。

## 8. 资料与核验边界

- SQLite [事务](https://www.sqlite.org/lang_transaction.html)与 [WAL](https://www.sqlite.org/wal.html)：单写事务、多读连接与本机文件条件；据此选择短事务持久队列，并发数仍需产品实测。
- Apple [Keychain Services](https://developer.apple.com/documentation/security/keychain-services)：macOS 系统凭据能力，不属于 Tauri 独占接口。
- Nginx [proxy_buffering](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering)：代理流式响应的缓冲配置；本文代理安全方案仍须实际部署验证。
- 仓库当前 `runtime_host.rs` 的全局 active 槽与 store v1–v5 是现状，不是新并发契约；历史证据按原版本保留。
