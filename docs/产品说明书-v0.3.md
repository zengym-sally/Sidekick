### 字体

中文苹方/思源黑体（UI 正文）+ Space Grotesk（拉丁与数字、wordmark）。大字号、紧凑排版；打包前核对随包字体许可与缺字回退。

### 桌宠形象设定（M1 定稿，矢量 SVG 实现）

一枚**穿小马甲的圆豆**：圆身、大眼、小马甲（跟班/店小二意象）。生命周期动画四态——

1. **待机**：呼吸起伏 + 随机眨眼。
2. **发现待办**：竖身举小本子，仅在待办签收入库成功后触发。
3. **提醒**：拍桌/举牌，头顶气泡弹「盯着呢，老板」+ 到期条目。
4. **完成致意**：鞠躬「是，老板」，在完成操作成功后反馈。

### 动效语言

待机=呼吸感，交互=spring 弹性（motion-v），提醒=气泡弹出+轻微弹跳，完成=鞠躬+打勾。**Operate 界面以扫描、确认、处理为主**：列表、确认卡片、迷你输入、设置表单不放持续背景与文字入场动效，不延迟可操作时间。

Vue Bits 保留在既定栈内，按组件引入；问候/独立展示区域的文字动效与 Aurora 为 P1 视觉增强，受品牌色约束，不使用彩虹效果。Aurora 当前组件依赖 `ogl`，部分组件使用 gsap 或 three.js，不能复制整个演示站的依赖。

工作模式关闭装饰动效，但保留静态提醒、未读标记与操作反馈；跟随系统减少动态效果设置。主窗隐藏时停止其动画循环，桌宠独立保持轻量。资源验收见 §三 3.7。

### 语气

轻快、有跟班的人味、不啰嗦；称呼用户“老板”；提醒文案带状态感（“老板，3 件事到点了”）。错误提示明确原因、影响和下一步，例如“老板，飞书没发出去，桌面提醒已保留，可重试”。

## 一、产品画像

### Platform

macOS 桌面应用（首发 macOS arm64，Tauri 2 打包 dmg；Windows 为后续可选）。最低 macOS 版本、开发与评审机器环境须在 M1 记录；当前未承诺某个系统版本已适配。

### Stack（已拍板）

- **壳与数据**：Tauri 2（Rust 核心：SQLite、调度器、飞书适配、系统通知）+ SQLite。
- **前端**：Vue 3 + Vite + TypeScript + Pinia + Tailwind CSS v4 + **Vue Bits**（动效组件）+ **motion-v**（动效基座）+ TDesign（功能基件：表单/表格/设置）。
- **选型依据**：沿用用户既有 Vue 3 能力，个人长期可维护性优先；Vue Bits 提供可选动效素材，motion-v 用于 Vue 动效。组件数量、星标数等变化信息不作为架构依据。具体依赖版本尚未锁定，M1 验证后记录版本矩阵；不能把“Vue 3”泛称当成全部组件兼容的证据。
- **LLM**：OpenAI 兼容可配置端点，配置模型见 §四。
- **待验证实现细节**：SQLite 迁移建议走 Rust 内的 SQLx 版本迁移；凭据建议通过 Rust keyring 的 macOS 原生存储后端访问系统钥匙串；飞书长连接 Rust 路径先做技术探针。均未安装或联调，见 §三与 O2。

### Users

首用户：曾亚明本人——每周 8 个会、8 份纪要、10 份文档、8–10 项决策事项，待办散落在妙记、纪要、邮件、日程和周报里，靠记忆跟闭环、容易漏项。以上为用户提供的工作负载背景，不是本产品实测基线。第二用户：作业评审人员（按运行说明安装验证）。

### Product Purpose

把散落在多个渠道的个人待办收进一个桌面入口：AI 从纪要/邮件/日程原文里抽取待办，**人确认后才入库**；到期由桌宠气泡与飞书机器人双通道提醒；每日自动出日报。成功标准：漏项率下降、录入耗时下降、“靠记忆跟闭环”变成“跟班替我盯”。

作业主线采用“粘贴一份真实结构的脱敏纪要 → 抽取 → 签收 → 到期双通道提醒 → 桌面完成 → 日报”。邮件、日历自动抓取仍在规划中，不作为主线的前置依赖。

### Positioning

个人单机的 AI 待办管家，桌宠形态。差异：①跨来源 AI 提取并人工确认；②桌宠存在感；③本地数据优先。P0 通过粘贴处理多类原文，P1 再自动抓取飞书邮件与日历，不把粘贴描述成 API 自动接入。

### Operating Context

macOS 常驻（桌宠+托盘）。关闭主窗不退出；主动退出、关机与系统休眠期间，本机不运行任务，不能承诺飞书远程指令处理或按时提醒。恢复后按 §三补偿。飞书长连接用于入站事件，出站提醒通过消息 API；接收连接故障与出站 HTTP 故障分别显示，不能把长连接在线直接当成发送成功。

### Capabilities and Constraints

见 §二。硬约束：①AI 抽取不直接写入正式待办，必须经确认卡片人工签收；②只接飞书一个渠道（机器人长连接、邮件、日历）；③不做团队协作与多端同步。用户已有自建飞书应用，凭据与权限在联调阶段配置。

### Evidence on Hand

用户提供的周报/workshop 背景包括 8 会/8 纪要/10 文档、决策事项“连续四周没人答复”、“人工跟催、状态靠记忆，容易漏项”。本轮未取得这些原始周报独立复核，不据此声称具体漏项率或节省时长。

### Product Principles

1. **AI 提取，人签发**——AI 录入、合并、改期、改优先级建议都先进入候选/差异卡片；点击签收或应用后，才修改正式待办。日报是只读总结，不能借日报写入待办。
2. **本地优先，外发可知**——SQLite 是权威记录；抽取时外发选定原文，日报时外发选定待办事实，飞书提醒外发必要摘要。API 密钥、App Secret、授权令牌进入系统钥匙串，外发边界见 §四与 O6。
3. **双通道目标，失败可追**——桌宠气泡 + 飞书机器人为两条产品提醒通道，系统通知是本机补充。分别记录结果，不以发送受理替代本人已读，不承诺休眠/离线下必达。
4. **小而完整**——录入→确认→跟踪→提醒→处理→统计闭环全通，先保证作业可运行与业务证据，再扩展 P1。

### Brand Commitments

本说明书 §〇 即品牌承诺；界面走 Operate 模式（扫描性、一致性优先），桌宠与少量动效承担品牌个性。状态同时有文字/图标，不只靠颜色；琥珀用于强调时搭配墨蓝文字，避免小号琥珀文字直接铺在象牙底上。

## 三、架构与数据模型

### 3.1 Rust 是权威服务，三窗口只表达与提交操作

```text
Tauri 2 (Rust，单实例)
├── 命令与事务：手工录入 / 候选签收 / 状态修改 / 身份与版本校验
├── SQLite：sources / candidates / todos / todo_sources / activity_events
│          reminder_jobs / reports / channels / fetch_logs / settings
├── 调度器：提醒与恢复补偿(P0)、日报(P0)、抓取/整理(P1)
├── 飞书适配：出站消息 API(P0)、长连接状态(P0)
│             本人指令(P1)、卡片回调(P1，路径先验证)、邮件/日历 API(P1)
├── LLM 适配：解析 → 本地结构校验 → 候选；报告 → 数据事实 + 文字摘要
├── 系统钥匙串：LLM key / 飞书 App Secret / 授权令牌（仅 Rust 读取）
└── 通知：桌宠事件与 UI 回执 / 系统通知提交结果 / 飞书发送结果
Vue 3 前端（三窗口，同一后端；各窗 Pinia 不是独立数据库）
├── 桌宠窗(P0)：透明 / 置顶 / 拖拽 / 气泡 / SVG 四态
├── 主窗(P0)：四视图 / 确认卡片 / 日报 / 设置；抓取面板与周报(P1)
└── 迷你录入窗(P1)：全局快捷键，复用候选确认；不加载重型背景
```

各窗口经窄 Tauri command 访问数据；后端提交事务后发版本事件，窗口重新读权威数据。事件丢失或窗口重新打开时重新读取；未提交不乐观显示“已保存”。不向前端开放任意 SQL、任意密钥读取或任意文件/网络访问。外部原文按纯文本展示，不能执行其中的指令、HTML 或脚本；模型无工具调用与文件权限。

### 3.2 AI 候选与正式待办分开，签收必须原子化

逻辑状态：原文 → 解析中 → 待确认/解析失败 → 已签收/已丢弃。AI 结果在签收前不得进入正式 `todos`、待办计数或提醒对象。**未签收候选是否允许在本机暂存也须由 O6 明确**；未获同意时只在内存展示，退出会丢失未签收结果，界面须提前说明。下表的候选持久化是待确认方案，不能用“不是正式待办”自行扩大存储授权。无论采用哪种暂存方式，签收事务都同时检查候选幂等键/终态、写 todo、挂来源、保存已处理结果、写确认与新增事件、建提醒；失败整体回滚。双击、重复命令、多窗口同时签收均只产生一次效果。

手工 C1 可直接保存；C2/C3/C4/C5/C15 的 AI 录入均进入同一签收路径。C12 建议必须显式应用。确认卡片显示动作标题、负责人归属、绝对截止时间与时区、原文引用、日期推断依据、重复提示；未知字段明确“未确定”。拒绝不触发提醒。报告仅总结已确认数据，不从原文悄悄补建事项。

### 3.3 数据字段覆盖多来源、多次提醒与可复核统计

下表为建议逻辑模型，不是已执行的建表结果。P1 专属字段/表在对应能力开工时再迁移，不为本作业构建通用流程引擎。

| 表 | 核心字段与约束 | 对应能力 |
|---|---|---|
| todos | `id, short_id(unique), title, notes, priority, status(todo\|doing\|done\|dropped), tags, deadline_at_utc(nullable), deadline_timezone(IANA), deadline_kind(none\|date\|datetime), deadline_local_date, deadline_text, confirmed_at, confirmed_by, created_at, updated_at, completed_at, deleted_at, version, schedule_version`；日期类保留用户选定日期与提醒时刻，无截止不安排到期提醒 | C1/C8/C14；人工确认审计 |
| sources | `id, channel_id, source_type(paste\|mail\|calendar\|bot), external_id, external_revision, content_hash, captured_at, authored_at(nullable), source_timezone(nullable), source_url, raw_text`；相同外部版本唯一；粘贴用规范化内容哈希；正文仅本地按保留策略存储 | C3–C6/C15；输入幂等 |
| candidates | `id, source_id, candidate_key, batch_id, payload, evidence_quote, date_anchor, parse_model_id, parse_status, review_status(pending\|accepted\|discarded), confirmed_todo_id, reviewed_at, version`；同一 source 的候选键唯一；重试同批结果不能覆盖已处理候选 | C2–C5/C12/C15；签收门禁 |
| todo_sources | `todo_id, source_id, candidate_id, linked_at`；关联唯一；一件事可对应多份原文，同一原文可含多件事 | 跨渠道来源追溯 |
| reminder_jobs | `id, todo_id, schedule_version, kind, channel(pet\|system\|feishu), scheduled_at_utc, status(pending\|running\|sent\|failed\|unknown\|cancelled), attempts, next_retry_at, lease_until, sent_at, displayed_at, external_message_id, error_code`；逻辑唯一键为待办+计划版本+提醒类型+通道+计划时刻；重试更新同一任务 | C9–C11/C16；补偿与通道结果 |
| activity_events | `id, todo_id, event_type, before_values, after_values, actor, operation_id(unique), occurred_at_utc, business_timezone`；保存创建/确认/完成/重开/改期/删除历史，不存凭据 | C14/C17/C18；按当时事实统计 |
| reports | `id, period_type(day\|week), business_date, timezone, version, status(facts_only\|generating\|ready\|failed), facts_snapshot, summary, model_id, generated_at, error_code`；同一类型+日期+时区只一份当前版本；重试保留事实快照 | C17/C18；生成幂等 |
| channels | `id, type(bot\|mail\|calendar), enabled, account_ref, owner_open_id, calendar_ids, credential_ref, scopes_snapshot, poll_interval_sec, cursor, last_success_at, connection_state, last_error_code`；Secret/令牌不入表，游标仅在本轮数据持久化后前进 | C22/C4–C6；账户与授权边界 |
| fetch_logs | `id, channel_id, run_id, trigger(manual\|scheduled\|resume), started_at, ended_at, status, cursor_before, cursor_after, fetched_count, new_count, duplicate_count, error_code, retry_count, next_retry_at`；不记原文/请求认证头；同渠道单次运行 | C4–C6；可诊断抓取 |
| settings | `key(unique), value_json, schema_version, updated_at`；仅存时区、提醒/日报时间、快捷键、工作模式、登录启动偏好、模型绑定、窗口位置、保留策略等非秘密；版本化校验 | C20/C21/C24 |

提醒时间不再挤在 `todos.remind_at` 单字段，来源不再依赖单个 `source_ref`。索引优先覆盖状态+截止、待发送任务+下次重试、外部来源版本键；批量确认与调度由单一后端协调，启用外键，约束与事务失败都须反馈。

### 3.4 去重以来源身份为准，语义相似只能建议

同一邮件使用渠道账户+message ID+内容版本；日历使用日历 ID+event ID+重复实例 ID+内容版本；机器人事件使用 event/message ID。消息重投先持久记录去重再执行业务；平台要求的应答不等待模型，处理超时或崩溃恢复用同一 operation_id。粘贴完全重复文本先展示已处理批次，允许显式新建一次解析，不重新生成已确认待办。

跨渠道同一事项、源文档改版后相似事项，只提示“可能重复”，用户可关联已有待办或确认新建；不按标题自动合并，不覆盖已有截止/状态。丢弃过的同一候选默认不反复弹出；来源发生实质变化时显示新版本和差异。原文修改/删除不删除本地已签收待办。

### 3.5 时间有锚点，休眠恢复有补偿

建议默认展示时区为 `Asia/Shanghai`，用户可改；默认值与提醒时刻待 O3 确认。存储使用 UTC 时间点 + IANA 时区 + 原始表达 + 日期类型；显示时标明本地时间与时区。跨时区旅行时，已确定的绝对时间不随系统时区悄悄移动。日期型事项保留原日期，变更应用时区前预览影响并确认。

| 情形 | 建议规则与验收样例 |
|---|---|
| 相对日期 | 以来源明确的写作/发言时间及其时区为锚；没有可靠来源时间则以本次解析时间为锚并显式提示。不能把旧纪要里的“明天”默认当成导入次日 |
| “下周五” | 周一为周首，指锚点下一自然周的周五；以 2026-10-28、Asia/Shanghai 为锚，日期是 2026-11-06；“本周五”为 2026-10-30。无时刻则按下项处理 |
| 只有日期/含糊表达 | 建议无时刻日期使用 18:00 并在卡片突出显示待确认；“周五”“月底前”“尽快”若语义不唯一或无法确定则不猜，保留未定截止，签收时可补 |
| 夏令时与非法时间 | 用 IANA 规则解析；不存在的墙钟时间或重复时刻要求选择，不自动挪动；固定语料覆盖夏令时切换与跨年 |
| 提醒计划 | 建议截止前 10 分钟、截止时各一次；逾期每天本地 09:00 合并一次，遇同一时点合并；确认时已过的提前提醒不补发，直接按当前状态建计划。无截止不编造到期提醒 |
| 休眠/退出/时钟变化 | Rust 调度器从持久化任务计算，不靠 Vue 的 setTimeout。每次启动、唤醒、网络恢复和时间变化后重算；醒来/重启后 60 秒内展示一条补偿摘要并尝试可用通道，不把每个错过时刻逐条重放；已完成/删除/旧计划版本不发 |
| 桌宠隐藏/全屏 | 保留未读提醒与托盘标记；桌宠重新出现时显示合并摘要。隐藏期间不能把 C9 记成“已展示”。全屏具体策略见 O4 |
| 日报 | 建议每天本地 18:30；按业务日期和时区生成一份。错过时点恢复后补最近一个已到生成时点的业务日，显示覆盖日期与数据截止时间，不伪造历史逐日已生成记录 |

应用状态含义：`todo`/`doing` 为未完成；`done` 有 completed_at；`dropped` 为明确取消，删除另有 deleted_at。逾期=未完成、未取消、未删除且截止早于当前时刻。今天视图按本地当天截止分组；本周按本周截止分组；逾期可同时在今天/本周中显示标记；已完成按完成时间查看。无截止单列“未定期”，不进入漏项率分母。

### 3.6 离线、重试与授权失败都有明确出口

| 场景 | 行为与验收检查 |
|---|---|
| 无网络/无 LLM 配置 | 手工录入、查看、完成与本地提醒可用；AI 原文保留本地草稿、显示待解析，不伪装提取成功。重新发送前仍显示原文与端点；用户取消/删除草稿后不再外发 |
| LLM 超时/429/5xx | 供应商配置 maxRetries 是上限，指数退避加抖动，尊重 Retry-After；一次交互总预算建议 30 秒且不突破 provider timeout，剩余预算不足停止并允许人工重试。解析可重新计费，提示重试，不无限循环；401/403/配置或结构校验失败不盲目重试 |
| 模型格式错误 | 本地校验字段类型、枚举、日期、来源引用；错误结果不能进入正式待办。可显示错误与原文，手工补录或显式重新解析；不把“structuredOutput=true”当成响应已合法 |
| 飞书发送失败/结果不明 | 可判定的临时失败使用同一提醒任务重试，建议最多 3 次（1s/5s/30s，限平台允许）；超时无法判断是否发送时标 unknown，能查回结果或有平台幂等键时先核对，不盲目重发；显示失败/未知，不能统计为触达成功 |
| 飞书长连接断线 | 分别显示未配置/连接中/在线/重连中/需重新授权；心跳、重连间隔及抖动优先遵循所用 SDK/服务端配置，平台外层重启退避封顶建议 60s，避免叠加两个重连循环；恢复后以事件去重和 API 游标补偿，不假设断线事件一定重放 |
| 入站事件/卡片 | 只接受绑定本人和预期单聊上下文；正文按不可信输入处理。以稳定 ID、operation_id 和 todo.version 校验；重放/旧卡片不再次执行。当前官方 SDK 资料对长连接回调支持存在需核实处，C16 必须独立通过路径测试 |
| 邮件/日历授权过期 | App ID/Secret 不替代用户授权；标明身份、scope、有效期；失败不推进游标。具体 API、账户可见范围、分页与刷新令牌方式须在 C4/C5 开工前核实，不默认自建应用已具备全部权限 |
| 数据库不可写/迁移失败 | 不显示保存成功；暂停写入与调度，不用空库覆盖原库；提供错误与备份恢复入口。日志只含错误码、任务 ID、耗时，不含原文或凭据 |

### 3.7 三窗口先做原生探针，再做视觉增强

| 技术点 | 研发约束与检查点 |
|---|---|
| 透明与点击穿透 | 透明像素不自动穿透。P0 建议小尺寸可交互矩形窗，避免大块透明区域拦截；拖拽手柄与按钮/气泡命中区分开。Tauri 的忽略光标事件接口作用于窗口，不能依赖已穿透窗口的 DOM hover 自行恢复；若提供整窗穿透，必须有托盘/快捷键恢复入口。像素级命中不列必交付 |
| 拖拽与多屏 | 统一逻辑/物理坐标转换，考虑 Retina 缩放、负坐标、菜单栏/Dock 工作区；保存显示器标识、相对位置与缩放。限制宠物与气泡可见，断屏后钳回可见区；双屏不同缩放、上下/左右布局与拔屏各测一次 |
| 全屏与 Spaces | always-on-top、所有工作区可见与全屏辅助窗口是不同机制。先测目标 macOS 的全屏、Mission Control、分屏与多显示器；建议 P0 不承诺覆盖其他应用全屏，用系统通知/飞书补充，O4 确认后定策略。不能以普通桌面测试推断全屏支持 |
| 全局快捷键 | 注册失败要提示并提供改绑；isRegistered 只查询本应用注册记录，不能用它证明没有其他应用占用。按按下事件触发一次，防止按住连开；中文输入法、权限状态、焦点恢复、Esc 各测。快捷键失败仍有托盘入口 |
| SQLite 迁移 | 建议 Rust SQLx + 带版本迁移，仅后端访问；官方 tauri-plugin-sql 也支持迁移，但前端直连写库会分散签收与调度约束，因此不建议双数据库入口。迁移前一致性备份；空库、旧测试库、失败中断三类验收；不承诺自动回滚任意旧 schema |
| 系统钥匙串 | 建议 Rust keyring + 明确选择 macOS 原生钥匙串后端，不把 community keyring 当官方 Tauri 插件；Stronghold 是独立加密 vault，不是系统钥匙串的同义词。先测签名变化、钥匙串锁定/拒绝、重启读取；失败停止调用，不回退明文 |
| Vue/motion-v | 建工程时锁定 Vue、motion-v、@vueuse/core、Vue Bits 所选组件与 TDesign 版本；按实际 peerDependencies 核对并运行 Vue 类型检查、构建、SVG/事件/卸载探针。官方包声明兼容范围只是必要条件，不是三窗口实测结果 |
| 依赖与资源 | 不引入 Vue Bits 整站依赖；P0 桌宠只用 SVG+motion-v，Vue Bits 选一个低成本组件验证接入，避免同时引入多套动画运行时。gsap/three.js/ogl 只在选择的 P1 组件确实需要时引入、懒加载并在隐藏/卸载时释放 RAF/WebGL。对比启用前后的 JS 产物、dmg 字节数、进程树 RSS、空闲 CPU；不得用 npm 包体积直接推断 dmg 或内存 |
| 权限与常驻 | 先解释提醒价值，在用户点击“发送系统测试通知/启用通知”时申请通知权限，拒绝可继续使用并给系统设置路径。开机自启指用户登录后启动，用官方 autostart 插件候选实现、默认建议关闭，不把它当开机登录前运行或防休眠服务；安装至 Applications 后再启用并实测注销登录 |

### 3.8 备份可恢复，重置不可误伤

P0 提供手动本地备份与恢复到测试目录的流程；迁移前自动生成备份。使用 SQLite 一致性备份 API 或等价的一致性导出，不在活跃 WAL 模式下只复制主 db 文件。备份包含数据库、非秘密配置与版本清单，不含钥匙串、认证头或令牌；数据库中的个人原文仍属敏感，目标位置必须由本人选择。默认不做云备份。

## 四、LLM 配置设计（对齐 WorkBuddy 配置格式）

### 4.1 两层结构兼容输入，Sidekick 扩展必须标明

参照本轮实际读取的 [providers.example.json](/Users/zengym/WorkBuddy/2026-10-28-16-43-52/config/providers.example.json) 与 [models.example.json](/Users/zengym/WorkBuddy/2026-10-28-16-43-52/config/models.example.json)。两份样例均为合法 JSON；仅验证结构，不代表其中端点、模型、token 上限与价格已可用或实测。

| 文件 | 沿用字段 | Sidekick 规则 |
|---|---|---|
| providers.json（连接层） | 根 `$comment`（可选）、`providers[]`；项目 `id/name/apiFormat/baseUrl/auth/extraHeaders/network/rateLimit/enabled/tags`；`auth.type=bearer`、`auth.apiKeyEnv`；`network.timeoutMs/proxy/retry{maxRetries,backoff}` | `apiFormat=openai-compatible` 为首期路径；baseUrl 为 API 根，统一拼接一次 `/chat/completions`；超时/退避按 §三交互预算约束，rpm/tpm 为 null 表示未声明而不是无限配额 |
| models.json（模型层） | 根 `$comment`（可选）、`models[]`；项目 `id/name/providerId/apiModelId/description/status/aliases/capabilities/limits/reasoning/pricing/defaultParams`；保留样例全部 capabilities、limits、reasoning、pricing 子字段 | providerId 必须存在且可用；价格 null 表示未知，不能算成零费用；capabilities 只是配置声明，实际结构化输出与参数支持需探测；模型层不放 URL/密钥 |
| Sidekick 凭据扩展 | `providers[].auth.apiKeyRef` | 这是新增字段，并非 WorkBuddy 样例已有字段；与 apiKeyEnv 二选一，两者都设则报错，不静默覆盖。引用只含钥匙串条目标识，不含密钥值 |
| 任务绑定 | 存在 settings 的 `default_model_id` 与 `task_model_overrides` | 不擅自给 WorkBuddy 文件新增必填根字段。P0 只要求全局默认；三类覆盖（快捷录入/粘贴与渠道/日报周报）为 P1 可选，未设回落全局；更复杂自动路由仍属 P2 |

导入时保留可识别元数据与未知扩展字段，不把整份 model 元数据透传为请求参数。校验唯一 ID、有效引用、禁用供应商与默认模型；被引用配置不能直接删除，先指定替代。成对校验成功后才提交配置，原子写文件并保留上一份可用版本；失败仍使用原配置。固定版本导入/导出语义需记录，**只承诺 Sidekick 能读这两份输入样例，不声称新增 apiKeyRef 可被 WorkBuddy 反向读取**。

### 4.2 密钥只在后端使用，Finder 启动也必须可用

- GUI 输入密钥后交给 Rust 写系统钥匙串，前端只获得“已配置/不可用”，不回读明文。飞书 Secret 与用户授权令牌采用相同边界；引用以稳定应用标识+账户/供应商 ID 区分。
- 建议优先采用 keyring 的 macOS 原生钥匙串后端；Stronghold 需要独立 vault 和解锁密码方案，不作为“系统钥匙串”替代名称。本轮仅提出选型，没有新增依赖。
- 兼容 apiKeyEnv，但 Finder 启动的 GUI 不保证继承终端变量；缺失时明确提示转用钥匙串或按运行说明提供环境，绝不把环境变量值写回 JSON。两条路径分别从安装包重启验证。
- extraHeaders 仅存非秘密固定头；Authorization、Cookie、x-api-key 等凭据不能放入明文 header 配置。日志、错误上报、连通性测试回显与备份统一脱敏。
- baseUrl/proxy 仅允许本人在设置中显式配置，导入配置先展示目标域名；默认 HTTPS，若需本机 HTTP 服务需显式确认。跨主机重定向不得携带认证头；原文和模型输出不能修改端点、请求头或任务绑定。

### 4.3 联通、合法输出与外发授权分开验证

连通性测试用不含业务原文的最小请求，报告供应商、模型、状态码、耗时、结构化输出是否可用，响应日志不显示敏感头。只连通域名不算模型可用。OpenAI 兼容不等于 reasoning/structuredOutput/所有参数通用：只映射本任务和该端点已验证的参数；不支持时提示或回到普通文本+本地结构校验，不私自更换供应商。

首次调用与变更端点时，在请求前展示将发送的数据类别与目标；抽取仅发送本人选定原文及必要时间/负责人上下文；报告只发送选定时间范围的事实字段。来源原文可能包含他人或公司信息，真实材料能否外发、允许的端点与保留政策由 O6 确认。演示先用脱敏数据，不把“本地优先”写成模型在本机运行。

### 6.2 AI 质量靠冻结语料，不靠演示挑样

固定 C3 的 10 份语料与至少 30 个原子行动项、C2 的 20 条自然语言；模型试跑前由本人完成人工答案。每个行动项登记 `fixture_id/item_id/动作标题/本人归属/截止或未定/原文证据/日期锚点`；涵盖无待办、他人任务、否定/已完成、重复、多任务一句、无日期、旧纪要相对日期、下周五与跨时区。调提示词使用另一组材料，不在验收语料上反复调参后报泛化效果。

- 抽取精确率=与人工答案一对一匹配的正确候选数/全部返回候选数；召回率=正确匹配数/人工标注应抽取数。多抽、重复、错误归属均计入错误；漏日期/错误时间的候选同时记字段错误，不用“用户能改”掩盖。
- 整条准确率用于 C2：动作语义、本人归属、截止时间（含该为空）均正确才算对；C3 另报这些字段的正确/总数，日期错误必须在确认卡片明显可见。
- 计时从提交到合法候选可操作；超时、无效 JSON、取消、供应商失败分开计数，失败不能从时延成功率分母删除。记录 provider/model ID、非秘密参数、提示词版本、请求耗时；不将原文上传到额外分析服务。

### 6.3 一份本地采集表就能支撑结论

可以用本地 CSV/表格记录，无需另建分析平台。逐项采集 `sample_id, phase(手工/试用/受控), source_key, source_type, authored_at, due_at/timezone, owner_confirmed, tracked_at, noticed_at, action_at, start_at, saved_at, item_count, missed_reason, evidence_ref`；提醒另加 `job_id, channel, scheduled_at, submitted_at, displayed_at, observed_at, outcome, error_code`；日报加 `business_date, generated_at, status, facts_check`。原文、凭据不进统计表，证据指向本地脱敏截图或测试记录。

每天约 10 分钟完成原文复核、对照时间戳与异常归因；期末保留原始行和计算公式。来源统计按创建时主来源归类，一件多来源待办只计一次，额外列“多来源关联数”；完成率=统计期内到期且未取消/删除事项中，在截止前完成的数量/同一到期集合数量，历史按事件重建，不能用当前快照覆盖先前截止。试用改期单列，不能靠延后截止“改善”完成率。

受控测试证明功能，真实试用观察业务效果，两者分表展示；8–10 项决策事项不是全部待办数，也不能直接当漏项率分母。未采集到的指标填“未测/样本不足”并说明原因。

## 七、非目标（本作业明确不做）

团队协作与共享待办、多端/移动端同步、子任务与项目甘特、除飞书外的渠道接入、桌宠主题商店、账号体系与云存储。

## 八、风险与待定项

### 技术与交付风险必须有停止扩展的条件

| 事项 | 影响 | 对策与检查点 |
|---|---|---|
| 飞书邮件/日历权限 | C4/C5 无法按时联调 | 已有自建应用不等于 mail/calendar 用户授权齐全；M1 核实账户、scope、接口与刷新方式，失败不阻塞粘贴主线，不冒称已自动抓取 |
| 飞书长连接实现与卡片回调 | Rust 无已验证接入路径；C16 接收方式可能受限 | M1 探针验证心跳/重连/事件与回调；没有证据不承诺官方 Rust SDK 已支持。若需要 sidecar 或公网回调，先交 O2，不自行改变架构 |
| 妙记 API 权限 | C7 不可做 | 已列 P2，MVP 用粘贴纪要替代 |
| 桌宠原生窗口行为 | 透明命中/多屏/全屏影响可用性 | M1 先测窗口而非先堆动画；全屏策略 O4 确认；托盘始终可恢复 |
| LLM 可用性、结构与业务数据外发 | 超时、误判、公司资料风险 | 最小测试、固定语料、本地校验、人工签收、脱敏演示；原文不指挥工具；真实资料启用前完成 O6 |
| 本地原文与备份 | 本地 SQLite/导出并非自动加密 | 凭据与业务库分开；只在本人账户与批准的目录使用，备份仍属敏感；保留/擦除范围由 O6 确认，不承诺数据库已加密 |
| 动效依赖 | 多窗口常驻 CPU/内存和包体超预算 | 按组件取依赖，隐藏即停止；M1/M3 同条件采样；超预算先砍 P1 视觉 |
| dmg 分发与评审环境 | 开发机可运行但评审机被 Gatekeeper 拦截 | M1 确定 O5 并做第二台试装，M4 复验；不用“包已生成”代替“可安装” |
| 周数、工时与真实试用 | P1 挤占实测和出镜时间 | O1 确认实际期限；P0 未过停止扩展；不足一周业务样本如实说明，不编补证据 |

### 需 owner 拍板事项（均未决）

| 编号 | 要选择的事 | 建议与另一选项 | 决定前的边界 |
|---|---|---|---|
| O1 | 实际截止日/每周工时，以及是否接受 C11 前移、C2 后移与 P1 不包干 | 建议按四周闭环基线，优先保证双通道/日报/测量；若时间更短，先减少 P1，而非取消人工签收或弱化双通道承诺 | 排期和调级仍是候选方案，不据此擅自开工 |
| O2 | Rust 长连接探针不通过时，是否接受官方 SDK sidecar | 建议先守住已定 Rust 核心做有时限探针；另一选择是批准 Node/Python 官方 SDK sidecar，但会增加打包、进程和安全维护成本；卡片回调不通则 C16 留规划 | 不引入 sidecar，不增加公网服务，不宣称连接已验证 |
| O3 | 日期、提醒与日报默认语义 | 建议 Asia/Shanghai；日期无时刻 18:00、提前 10min/到期提醒、逾期 09:00 摘要、日报 18:30；也可要求无时刻必须手填并自选提醒时间 | 有歧义先呈现确认，不把建议默认值当用户同意 |
| O4 | 全屏空间是否必须展示桌宠 | 建议 P0 不覆盖其他应用全屏，通过系统通知/飞书补充；若全屏桌宠是体验硬要求，则需要独立原生验证和额外排期 | 不承诺 always-on-top 已解决全屏；隐藏期间不算气泡触达 |
| O5 | 签名/公证、评审机器与飞书演示访问方式 | 建议有账号条件时做 Developer ID 签名+公证并在第二台 arm64 试装；另一选择是明确限定现场本人演示与可接受的评审安装方式，由课程规则确认 | 不购买账号、不发包、不共享凭据；真实双通道必须有 live 证据，模拟不能替代 |
| O6 | 真实公司材料可发往哪些 LLM 端点；未签收 AI 候选能否本地暂存；正文/备份保留与重置范围 | 建议演示脱敏，真实资料仅用已获授权端点；候选暂存有利于重启恢复，但需明确许可与保留期；正文保留多久、备份位置、重置是否删凭据需本人确认 | 不外发真实材料；未签收 AI 结果未获暂存同意时仅在内存；不设自动删除，不声称企业数据边界已获批 |
| O7 | 资源警戒线是否适合本机与作业用途 | 建议固定机型按 §三测 CPU/RSS/dmg，并以删除装饰组件优先；也可先测空壳建立基线后定预算 | 文内 2%/250 MiB/50 MiB 只是拟定预算 |
