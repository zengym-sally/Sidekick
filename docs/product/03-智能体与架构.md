## 1. 班班统一对外，三个角色按任务执行

| 内置 ID | 角色 | 输入与职责 | 输出 |
|---|---|---|---|
| `organizer` | 事项整理 | 理解文本／链接，识别来源，调用 lark-cli 等内置读取技能，提取和整理新事项 | 带来源依据的候选卡片、重复提示、候选修改结果 |
| `tracker` | 进展跟踪 | 将新资料与已有事项关联，理解进展、识别关键变化、准备跟进材料 | 可自动附加的进展线索、待确认变更、催办草稿 |
| `advisor` | 工作参谋 | 基于个人事项与进展提出今日重点、安排建议和日报复盘 | 只读建议与报告，数字引用应用计算结果 |

角色是固定业务定义，共用本地 Runtime，按任务创建执行上下文，不按角色常驻三个服务。不为每个渠道另建智能体。入口和当前操作决定任务分发，班班不增加可供用户创建的第四类通用智能体。

智能体负责理解、推理、选择技能和产出建议。正常业务路径的调度、保存、用户签收、正式状态修改和发送结果由应用业务层执行，签收在业务接口中校验。按新增共识开放通用 Bash 后，**该保证不覆盖脚本直接改文件的绕过路径**；本产品不声明文件级强隔离。

## 2. 目标架构保留既定栈，增加随应用分发的 JS 执行进程

```text
Vue 3：桌宠窗 / 主窗 / 快捷录入窗
  └─ Pinia、TDesign、Tailwind v4、motion-v、按需 Vue Bits
             ↕ 窄命令与任务/状态事件
Tauri 2 / Rust 业务宿主
  ├─ bootstrap：定位 workspaceRoot，管理工作目录切换
  ├─ SQLite：事项、候选、证据、历史、任务、提醒与日报
  ├─ 签收与状态事务、调度、去重、通知、托盘、窗口管理
  ├─ 系统钥匙串、模型配置与来源连接状态
  └─ 本地 Runtime 生命周期与 IPC
             ↕ 结构化任务、进度、结果、取消
本地 JS Runtime（随包携带，非云服务）
  ├─ 工程内 Pi 源码构建：agent-core + pi-ai + pi-mcp
  ├─ organizer / tracker / advisor 固定定义
  ├─ Skills 加载器 + Read / Bash 工具
  │    ├─ lark-* 技能 → lark-cli / 脚本执行
  │    └─ Coremail：第二阶段接入读取技能
  └─ MCP 客户端 → stdio / Streamable HTTP → AgentTool
```

正常业务写入由宿主管理，前端与 JS Runtime 通过业务命令提交结果。多窗口 Pinia 只承载界面状态；重新打开或丢失事件后读权威数据。宿主事务成功后才显示已保存或已完成；不将这一正常路径设计表述为通用 Bash 无法访问数据库。

跨进程契约包含任务 ID、类型、输入引用、角色、配置版本、工作根／任务 cwd、进度、结果、错误与取消状态。模型调用按需获得本次凭据，前端不回读明文。模型可调用已提供的 Bash／MCP 工具；业务资料本身不构成新增业务授权，默认角色仍遵守事项签收和不代发催办等规则。

### Pi 源码进入开发工程，用户数据进入工作目录

采用 Git subtree 将 Pi 源码纳入工程的 `vendor/pi/`，固定上游提交、保留许可证和本地修改记录。保留其 workspace、锁文件与内部包关系，从同一快照构建所需依赖闭包，避免本地源码与注册表上另一版本 Pi 混用。后续合入上游时审查差异并重跑相关探针。

不以 submodule 作为首选，避免普通检出遗漏源码；直接拷贝快照虽简单，但升级差异需要额外维护。保留 `agent-core` 为业务 Runtime，按需复用 coding-agent 源码里的技能加载器、Read／Bash 工具；不启动完整 coding CLI 或 TUI。Bash 工具牵连部分渲染依赖，必须实测构建闭包，不能假定拷几个文件就能独立工作。

源码在工程中，编译产物和内置资源随安装包分发，使用期数据在工作目录。基线1.1文档交付时仅定义方案，尚未拉取、复制、修改或构建 Pi；后续 S0 的实际源码集成与探针状态见[实施计划](05-第一阶段实施计划.md)，不等于生产业务已建成。

## 4. 一个可配置工作根目录管理应用数据

默认使用 Tauri 应用数据目录下的 `workspace/`，设置中可更换。独立的 `bootstrap.json` 留在固定应用数据目录，只记录工作根位置与引导版本；秘密继续由系统钥匙串或各工具已验证的凭据机制管理。

```text
workspaceRoot/
├── config/
│   ├── app.json
│   ├── providers.json
│   ├── models.json
│   └── agents/              # 仅三个固定角色的配置
├── data/sidekick.sqlite
├── runs/<runId>/           # 每次任务的资料、中间结果与产物
├── skills/<skill-name>/    # SKILL.md 及完整支持文件
├── mcp/servers.json
├── logs/
└── backups/
```

目录是应用级单根，首版不做多工作区并发或目录合并。根路径规范化并由宿主持锁；任务默认 cwd 为自己的 `runs/<runId>/`，可按执行需要指定其他目录。**cwd 只是相对路径起点，不能限制 Shell 对目录外的访问。**

切换前停调度与运行任务，关闭数据库；迁移使用一致性备份处理 SQLite/WAL，校验配置、数据与关联后才原子切换引导指针，失败继续使用原根并保留原数据。目标为已有完整工作根时校验兼容版本，不自动合并；切换后技能路径和未完成任务引用重新定位。内置资源升级不覆盖用户工作目录。

lark-cli 配置与登录态的重定向、凭据落点及迁移能力仍需按实际版本验证，不能承诺它们已经全部归入此根目录，也不能依赖开发者本机的全局登录态。

## 5. Skills、Bash 和 MCP 共同组成可用工具层

### 完整技能包存放在工作目录，按需加载

链接输入时，由事项整理智能体识别飞书资源类型，加载对应技能，选择读取工具；不是让用户手选命令。定时收集由宿主触发，技能处理读取与分页，应用保存来源身份、游标和结果。新资料再进入整理与跟踪，重复内容不重复消耗模型。

首批内置飞书会议／妙记读取、消息检索与上下文读取、机器人提醒及卡片回调适配。妙记、智能纪要、Docx 是不同资源，应按链接实际类型读取，不能互换标识。@ 本人的检索覆盖范围、上下文可读性及分页需在真实账号验证，不以命令存在证明能完整抓到。

2026-10-29 本机核查到 28 个 `lark-*` 技能目录，涉及 `references/`、`scenes/`、`scripts/` 等支持文件；这是调研规模，不表示所有业务都成为首版功能。产品完整引入所需包及跨包依赖，安装资源保留内置基线，首次将完整包放入工作目录 `skills/`。用户可添加、修改、重新扫描和显式恢复内置包；升级不得静默覆盖其修改，恢复前说明覆盖范围。新包与内置包同名时明确报告冲突，不随机选一个。

加载器显式扫描产品技能目录，先索引名称、描述和位置，任务相关时再读正文及相对引用；不默认遍历用户全局技能和上下文。修改、添加技能不创建新智能体。运行记录保留实际使用的技能与内容标识；重新扫描对新任务生效，已加载正文不在执行中静默替换。Pi 提供相关加载接口，但需要产品显式接入。[技能机制](https://github.com/earendil-works/pi/blob/ad702637fdf6fbd3f965c5dba0b14bae100b74eb/packages/coding-agent/docs/skills.md)、[加载源码](https://github.com/earendil-works/pi/blob/ad702637fdf6fbd3f965c5dba0b14bae100b74eb/packages/coding-agent/src/core/skills.ts)

本机 `lark-cli 1.0.98` 实际为 `@larksuite/cli` 的 Node 命令入口，可从 Shell 调用。产品必须自带所需技能定义与适配，不依赖 Codex 插件或私有绝对路径；CLI 复用／随包分发、独立配置与登录引导先验证。命令及技能存在不等于真实读取成功。

飞书读取使用用户身份，机器人提醒使用应用身份。长连接接收与出站发送分别监测；选定 CLI／事件入口必须验证 `card.action.trigger` 的接收和结果反馈。卡片完成／稍后提醒已是首批承诺，通路不成立时应报告阻塞，不能悄悄改成只读提醒。具体卡片数据按 lark-cli 的受支持生成流程构造，不凭旧 SDK 说明断言回调一定可用。

Coremail 第二阶段先核实公司实际开放的读取方式，再选择协议或浏览器多步骤技能；失效登录、验证码等允许暂停等待本人处理。首批只保留适配位置，不宣称已可无人值守抓取。

### 通用 Bash 执行本机脚本，业务签收不等于脚本隔离

向三类内置角色提供 Read 与 Bash 工具，复用 Pi 源码中的 `createBashTool` 等能力；支持 cwd、环境、输出流、退出码、有界超时、取消和子进程清理。任务中可调用 `lark-cli`、技能附带脚本或本机已有命令，不把唯一执行能力写死为某个飞书连接器。[Bash 源码](https://github.com/earendil-works/pi/blob/ad702637fdf6fbd3f965c5dba0b14bae100b74eb/packages/coding-agent/src/core/tools/bash.ts)

普通 Bash 继承当前用户可用的执行能力，不加沙箱、命令白名单或逐命令审批。正常业务接口强制确认；脚本可直接访问文件甚至改库的事实不被隐藏，也不承诺能阻止这种绕过。MCP 工具亦不新增逐工具审批，默认角色的业务动线与签收规则保持。

产品负责定位随包 Node 和 lark-cli、构造进程环境，不能假设 Finder 启动继承终端的 nvm／PATH。调用超时须由产品设置，不沿用 Bash 可无限等待的默认；取消须清理所属子进程组。应用托管的输出经截断与脱敏记录，完整业务产物落本次任务目录；不承诺能强制约束任意自定义脚本自身的文件写入。

### MCP 首版实际连接并注册工具

读取 `mcp/servers.json`，使用 Pi `pi-mcp` 客户端接入 stdio 和 Streamable HTTP。服务配置含稳定 ID、传输类型、启用状态、命令与参数或 URL、必要环境／请求头的凭据引用；它是 Sidekick 的配置契约，不假定 Pi 会自动读取这个目录。工具以服务命名空间注册给内置智能体，处理同名冲突、输入 schema、结果／错误、超时、取消与服务生命周期。[MCP 客户端](https://github.com/earendil-works/pi/blob/ad702637fdf6fbd3f965c5dba0b14bae100b74eb/packages/mcp/README.md)

设置页显示连接、工具列表、错误和服务要求的登录状态，支持刷新、断开；配置错误或缺依赖不能显示已连接。秘密在运行时按引用注入，不写入明文配置和日志。具体服务认证与 Pi 的适配、重连和关闭行为在探针核实，不承诺所有 HTTP 服务无需认证即可调用。首版不建设 MCP 市场或复杂编排。

随包 Node 保障产品自身 Runtime 和配套 CLI；用户额外配置的脚本／MCP 服务仍需具备其运行依赖，缺失时明确提示。基线1.1补充调研快照为 `ad702637fdf6fbd3f965c5dba0b14bae100b74eb`，与前述初选比较快照区分；该调研轮未构建、连接或执行工具。后续实施证据见实施计划。

## 6. 供应商、模型与智能体偏好分层，避免重复填密钥

沿用 WorkBuddy [providers 样例](/Users/zengym/WorkBuddy/2026-10-28-16-43-52/config/providers.example.json)与 [models 样例](/Users/zengym/WorkBuddy/2026-10-28-16-43-52/config/models.example.json)作为兼容输入，样例中的模型能力／额度不视为实测。

| 配置层 | 目标契约 |
|---|---|
| `providers.json` | 保持 `$comment`（可选）＋`providers[]`；项目保留 `id/name/apiFormat/baseUrl/auth/extraHeaders/network/rateLimit/enabled/tags`；`network` 保留超时、代理及重试字段 |
| `models.json` | 保持 `$comment`（可选）＋`models[]`；保留 `id/name/providerId/apiModelId/description/status/aliases/capabilities/limits/reasoning/pricing/defaultParams`，模型层不存密钥或端点 |
| 凭据引用 | 兼容 `auth.apiKeyEnv`；Sidekick 扩展 `auth.apiKeyRef` 指向钥匙串，二选一且不静默覆盖。Finder 启动不保证继承终端变量；缺失时引导配置，不写回明文 |
| 智能体偏好 | 应用设置保存默认模型及各固定角色的模型覆盖、可视化偏好、补充指令和版本；未覆盖时继承默认。角色 ID、基础职责和关键业务规则固定 |

导入保留模型元数据，校验唯一 ID、供应商引用、默认绑定与禁用状态；未知价格保留未知，不当免费。配置成对校验后再保存，被引用项修改／删除须处理引用。运行任务固定使用启动时的配置快照，修改只影响新任务，恢复默认只改对应偏好。

GUI 提供供应商／模型管理、导入、最小调用测试和三个角色的调优页。调整补充说明后可用样例试跑，只预览候选与建议，不修改真实事项或混入真实收集批次。能力声明不能替代结果校验，不将整份 reasoning 等元数据直接透传给任意兼容端点。

应用自行管理的 API Key 等秘密使用 macOS 钥匙串，原生 keyring 后端为待验证候选；Stronghold 是独立 vault，不等同系统钥匙串。`extraHeaders` 只保存非秘密固定头，认证信息使用凭据引用，配置、日志和备份不回显密钥。lark-cli 凭据落点先核实，不假称其已入钥匙串；Sidekick 不将令牌复制进业务库或日志。用户已明确：配置内容直接交给所选模型，不新增外发授权或权限管理产品功能。

## 7. 保存业务台账与证据，重试不重复写结果

以下为逻辑对象，建表和字段细化留给对应开发切片，不在本轮生成 DDL。

| 对象 | 最小职责 |
|---|---|
| 事项 | 稳定 ID、执行／跟进类型、实际负责人、标题、优先级、标签、状态、截止、下次跟进、确认／完成时间、版本；时间点存 UTC 并保留时区与原表达 |
| 来源 | 类型、账户、外部身份／版本、来源链接、原文、内容哈希、源时间、拉取游标；区分源发生时间与导入时间 |
| 候选与变更 | 来源引用、结构化结果、原文依据、处理终态、目标事项与预期版本；与正式事项分开保存 |
| 事项来源关联与进展 | 一项多来源；自动／人工关联标记、摘要、证据、时间和用户纠正记录；不能仅按标题自动合并事项 |
| 活动历史 | 签收、完成、改期、负责人变更、删除及操作 ID，供同步与历史统计使用 |
| 业务任务与提醒 | 类型、输入／结果引用、配置版本、幂等键、进度、尝试次数、下次执行、通道结果、飞书 message_id、失败或未知状态 |
| 日报与设置 | 业务日期、事实快照、生成状态；模型绑定、智能体偏好、来源周期、显示与提醒偏好等非秘密设置 |

签收事务一次完成终态校验、事项写入、来源关联、活动记录和提醒计划；失败整体回滚。完成或删除取消未发提醒；改截止或下次跟进时间时提升版本、使旧计划失效并重建计划；稍后提醒只改提醒计划。过期卡片或旧建议不能覆盖新编辑。

来源外部身份＋版本、候选键、业务操作 ID 负责精确去重；语义相似只提示关联。自动进展附加须带证据键并去重，用户已纠正的关联不能被同一资料再次自动加回。

宿主保存任务与来源进度，模型中断可重新整理；已经确认的结果不被重试覆盖。只恢复有限业务任务，不保存或承诺恢复完整模型思考过程。临时失败有界退避，授权／配置错误停止，发送超时结果未知先核对，不能当成功或盲目重发。

日报数字由业务层按时间范围与历史计算，多来源事项只计一次，延期／取消保留事件；智能体仅用事实写总结。没有实测前不承诺精确率、性能、触达率、包体或资源占用已达标。

技术探针及真实使用证据的要求见[分期交付与验收](04-分期交付与验收.md)。
