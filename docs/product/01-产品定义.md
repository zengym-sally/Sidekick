## 1. 做一款自己愿意用、同事也容易上手的 AI 待办管家

跟班是 macOS 桌面 AI 待办管家，以桌宠“班班”陪伴用户工作。它从材料中发现事项，帮用户确认、安排、提醒、跟进和复盘，统一管理“待我处理”和“待我跟进”。

产品源于真实工作：本人每周约 8 个会、8 份纪要、10 份文档、8–10 项决策事项，信息散落，闭环靠记忆。这是用户提供的背景，尚不是效果测量基线。首批面向本人和有类似工作方式的同事试用，逐步形成可推广的精美产品。

**核心体验：用户面对一个班班，背后由固定内置智能体完成工作。** 日常以卡片和今日工作台为主，对话辅助整理；智能体配置面向偏好与调优。

## 2. 先打通四类入口，Coremail 下一阶段接入

分级：**P0**＝首批同事试用版必交付；**P1**＝首批之后分期交付，Coremail 优先、语音另排；**P2**＝后续候选，不构成承诺。🤖＝由内置智能体承载的业务能力。

## 3. 自动盯进展，关键决定仍由用户签发

| 动作 | 产品规则 |
|---|---|
| 创建正式事项 | AI 提取结果先成为候选，用户签收才写入正式事项；手工表单可直接保存 |
| 更新进展线索 | 可自动关联、附加摘要与来源，明确是“新发现的进展”；用户可纠正关联 |
| 改完成状态、截止、负责人 | 智能体提出建议，用户确认后应用；不能从“已提交”直接推断“已验收完成” |
| 调整今日重点 | 提供建议，用户可调整；建议本身不改正式事项的截止和状态 |
| 对外沟通 | 生成催办草稿供本人使用；首批不代发给他人 |
| 模型调用 | 内容直接送往用户配置的模型服务，不新增外发授权、逐批同意或权限管理模块 |

上表约束适用于产品正常业务接口与默认事项动线。首版开放通用本机 Bash，不增加沙箱或逐命令审批；因此不承诺从文件层阻止脚本绕过业务接口。MCP 同样不引入逐工具审批，但不自动扩展已确认的业务来源和代发催办等产品功能。

应用级工作目录容纳核心配置、数据库、运行产物、Skills、MCP 配置、日志与备份，允许更换；引导配置和系统钥匙串独立保存。技能可添加、修改和重新加载，智能体仍固定三个；MCP 首版实际支持 stdio／Streamable HTTP 连接、工具注册、状态与错误反馈，不只是预留目录。目录及加载规则见[架构文档](03-智能体与架构.md)。

## 4. 品牌有个性，工作界面保持清晰

| 项 | 已定规范 |
|---|---|
| 名称与昵称 | 跟班／Sidekick；班班；wordmark 使用小写 `sidekick` |
| 定位语 | **「盯着呢，老板。」**／**"On it, boss."** |
| 形象 | 穿小马甲的圆豆，SVG；待机、发现事项、提醒、完成致意四态 |
| 品牌色 | 墨蓝 `#1F3A5F`、深墨 `#16283F`、琥珀 `#C8872B`、象牙 `#F6F3EC`、砖红 `#B4442C` |
| 字体 | 中文苹方／思源黑体；拉丁与数字 Space Grotesk，随包字体需核对许可 |
| 界面 | Operate 模式：扫描与操作优先；动效用于反馈和桌宠表现，工作模式减少装饰动效，保留提醒 |

不使用彩虹多色、玻璃拟态和重边框；状态同时有文字或图标。精美程度纳入真实安装版的视觉与交互验收。

## 5. 个人本地产品边界保持明确

首发 macOS arm64。技术栈维持 Tauri 2＋SQLite＋Vue 3＋Vite＋Pinia＋Tailwind CSS v4＋Vue Bits＋motion-v＋TDesign，新增的 Pi 承载方式见架构文档。

不做团队共享、给他人派单、多端／移动端同步、子任务／项目甘特、桌宠主题商店、账号体系与云存储。来源限定为飞书及下一阶段 Coremail。用户不能新增智能体；不建设开放技能市场或通用助理平台。
