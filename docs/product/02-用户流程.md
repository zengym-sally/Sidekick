# 跟班的使用流程：收进来、签收、盯进展、做闭环

> 产品规划基线 1.1｜2026-10-29。
> **全部能力均为规划，未经实测。** 范围以[产品定义](01-产品定义.md)为准；本篇说明目标使用流程。

## 1. 首次使用先完成一次小闭环

| 步骤 | 用户操作 | 班班的反馈 |
|---|---|---|
| 安装与认识 | 安装应用，认识桌宠、托盘和今日工作台 | 说明关闭主窗仍常驻，托盘可退出 |
| 工作目录 | 直接使用默认目录，或在设置中选择应用工作目录 | 建立配置、数据库、运行与技能目录，显示当前路径及打开目录入口 |
| 配置模型 | 选择预设、导入配置或填写个人 API Key／公司网关，做连通性测试 | 显示选定模型是否真正可调用；保存后可直接分析资料，无额外外发确认 |
| 完成第一条 | 可先手工记录；或粘贴一段文本，查看候选并签收 | 展示原文依据、事项字段与签收结果，让用户先体验价值 |
| 接入飞书 | 跟随引导完成应用配置／用户登录，设置收集周期 | 分别显示资料读取连接与机器人提醒状态，可手动测试 |
| 个性化 | 可选填写工作偏好，为三个内置角色调整模型或补充说明 | 默认配置可直接使用，支持恢复默认 |
| 工具扩展（可选） | 在 Skills 目录放入完整技能包，或填写 MCP 服务配置 | 重新扫描技能；连接 MCP 并显示工具、状态或错误，不要求创建新智能体 |

无模型连接时仍可手工管理事项；未连接飞书不阻塞表单与文本入口。飞书资料读取需要实际可用的用户身份，机器人提醒使用应用身份，二者不混同。产品不另建权限管理页；飞书平台本身要求的登录与接入步骤仍需引导完成。

设置中可打开工作目录、重新扫描 Skills、刷新 MCP 连接。添加技能时保留 `SKILL.md` 及其参考文件、场景和脚本；MCP 显示未配置／连接中／已连接／失败／需登录等真实状态，未连接不能假称工具可用。更换工作目录时暂停任务，迁移校验成功后切换；首版使用一个应用级根目录，不提供多工作区并发或目录合并。

## 2. 四类入口汇入同一套事项与候选

| 入口 | 用户动线 | 结果 |
|---|---|---|
| 表单 | 打开快捷入口或主窗 → 填标题及必要字段 → 保存 | 用户明确填写的事项直接保存 |
| 文本 | 粘贴原文 → 发起整理 → 查看本次候选 | 候选进入统一待确认区，尚未成为正式事项 |
| 妙记链接 | 粘贴链接 → 班班识别资源类型并调用对应技能 → 显示读取、分析进度 | 有效原文进入整理；链接不可读则显示原因，不虚构事项 |
| 飞书主动收集 | 配好周期后后台运行，也可点击手动收集 | 新内容形成候选；涉及已有事项的内容进入进展跟踪 |

快录入口统一接收文本和链接，用户不用先选智能体或技能。后台收集结果进入待确认区，不自动签收；新资料与重复资料按来源身份去重。

链接处理时，班班按任务读取 Skill，再通过 Bash 调用 `lark-cli` 或脚本；需要时也可调用已连接的 MCP 工具。界面呈现任务进度与结果，运行产物落到本次任务目录。工具按配置直接执行，不增加逐命令／逐工具审批；相关业务通过正常接口提交候选和关键变更时，仍执行签收。通用 Bash 以当前用户权限运行，工作目录不是文件访问沙箱。

第二阶段 Coremail 复用同一流程：读取技能 → 新事项候选／已有事项进展。具体读取方式需先验证；“没有业务 API”不直接决定采用浏览器自动化。语音仅保留明确的规划占位。

## 3. 卡片负责确认，对话辅助批量整理

候选卡片展示：标题、待我处理／待我跟进、实际负责人、截止时间、下次跟进时间（适用时）、优先级、来源原文、日期推断与重复提示。

用户可以直接编辑、丢弃、选择关联已有事项，或批量签收。也可输入“第三条改到周五”“这两条是我要跟进的”，先预览修改后的卡片，再确认入库。**正常业务接口只接受已签收的正式变更；通用 Bash 的边界见前节。**

相对日期以可靠的源发生时间与时区为锚，缺失时明示使用解析时间，不能把旧纪要的“明天”当成导入次日。日期只到“周五”或语义有歧义时，卡片保留原表达并提示补齐；需要到点提醒却没有可执行时点时，提示设置。无截止的事项允许记录，在完整清单和未定期分组可找到，不编造时刻。

签收完成后才进入正式事项、今日建议和提醒计划。重复点击只创建一次；已拒绝候选不会因相同资料重拉反复出现。待确认草稿与正式事项分别保存，重启后应能继续处理；草稿不进入正式事项计数。

## 4. 每天从今日工作台开始，再进入具体事项

主界面首先呈现“今天待我处理、今天待我跟进、待确认”，班班提供重点与安排建议。完整清单支持日期、状态、负责人和标签筛选，可查看本周、逾期、已完成及未定期事项。

| 事项类型 | 主要操作 | 应区分的时间 |
|---|---|---|
| 待我处理 | 执行、编辑、完成、延期或删除 | 我的截止时间与提醒时间 |
| 待我跟进 | 查看执行人和进展、准备催办草稿、设置下次跟进、验收完成 | 对方交付截止与我下次跟进时间，可不同 |

今日建议引用已确认事项与已知证据；调整展示顺序不等于改正式截止。删除需明确确认，保留必要历史用于复盘。待确认内容独立分组，不伪装为已承诺的工作。

## 5. 后续线索自动记下，关键结论再确认

例如原事项为“张三周五提交方案，我负责验收”。飞书新消息说“方案已发，请查收”：

1. 进展跟踪智能体将其与原事项关联，附摘要、原文、来源时间，标记为新发现的线索。
2. 事项仍保持当前状态，界面提示可能已交付、等待本人验收。
3. 用户可以纠正或取消关联；若认定完成，再手动完成或接受完成建议。
4. 识别到延期、负责人变化等，也展示前后差异，确认后才修改。

催办草稿可参考这些线索生成，由本人复制、修改和联系对方。首批不替本人对外发送催办，也不向他人派单。

## 6. 到提醒时刻，能看见，也能马上处理

| 位置 | 可做什么 |
|---|---|
| 桌宠气泡 | 看条数与摘要，进入相关事项，查看进展和处理 |
| 系统通知 | 在系统允许时补充提醒，进入桌面处理 |
| 飞书提醒卡片 | 看事项、时间与状态，执行“完成”或“稍后提醒” |

“完成”是用户明确操作，更新正式状态并取消未发的旧提醒；“稍后提醒”只改提醒计划，不改截止时间。飞书按钮必须绑定稳定事项 ID，重复或旧卡片点击不会误改其他事项。复杂编辑与新事项签收打开桌面端完成。

飞书端操作依赖本机跟班运行及网络可用；卡片回调未执行时不能显示已完成。系统权限、专注模式或窗口隐藏可能影响可见性，各通道结果分别记录，不承诺绝对必达。

## 7. 一天结束，用事实生成日报

在用户设置的每日时点生成应用内日报，包含今日新增、完成、逾期、重要进展与明日重点。计数来自数据库，智能体负责解释和建议；未经确认的进展保留“新线索／待核实”标记，不计为完成或正式改期。建议引用具体事项，不从报告直接创建或更改事项。

模型失败时保留事实汇总并提示可重试，不将事实版标成 AI 生成成功。首批不自动推送日报到飞书，也不把日报变成向他人汇报的自动发送流程。

## 8. 中断可解释，重开能继续

以下为开发默认行为，须按[验收清单](04-分期交付与验收.md)验证：

| 情形 | 用户看到的行为 |
|---|---|
| 关闭主窗 | 托盘与桌宠按设置常驻，后台收集和提醒继续 |
| 主动退出／电脑休眠 | 本机停止或暂停处理，重新启动／唤醒后补拉新资料、合并补偿提醒，不逐条轰炸 |
| 取消一次整理 | 停止后续执行，已产生的候选保留并可清除；已签收事项不回滚 |
| 模型、网络或来源失败 | 显示正在处理、失败或待重试；保留输入，不把空结果当成功，不无限重试 |
| 重启或任务崩溃 | 从保存的业务任务和来源进度恢复，可重新整理但不能重复创建或覆盖已确认结果 |
| 后续 Coremail 登录失效 | 暂停该来源并提示本人重新登录；需人工交互时等待，不循环尝试 |

桌宠支持位置恢复、显隐与工作模式；多屏切换或拔屏后须可找回。全屏空间内的具体窗口表现与系统兼容性在技术探针验证，不用普通桌面截图代替。
